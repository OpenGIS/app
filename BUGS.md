# Bugs

1/ There is a bug with Chrome desktop for mac (macOS only, is fine on Windows) where the map is not zoomable using the mouse scroll wheel. The app works correctly everywhere else tested, including Chrome mobile. Instead of zooming the map, the entire app gets "pulled" up and down, indicating that the browser is treating the map gesture as a scroll instead of a zoom. Diagnose this issue and implement a fix.

2/ The GPX export function works on Desktop but does not work on mobile. When the export button is clicked on mobile, the loading indicator is displayed but the page hangs.

3/ **[FIXED]** as shown in the info-open screenshots, when the info panel is shown by default, the maplibre attribution is expanded and the the attribution is duplicated. instead, when the info panel is shown, the maplibre attribution should be collapsed, no need for drag end in this instance. The chip's collapsed state is now derived from the pane's visibility (`collapsed = dragged || isInfoVisible`): it collapses whenever the Info pane is open — including the desktop auto-open at load, so the credits appear only once in the pane's sticky footer — and expands again when the pane closes. The first map drag still latches it collapsed permanently, matching MapLibre's built-in control.

4/ On live loads, a glyph that arrives after MapLibre's symbol-placement pass can leave its label missing until the next interaction — MapLibre does not re-place symbols when a glyph becomes available. The E2E harness works around this by forcing a symbol re-placement after map-idle (`waitForMapPainted` in `tests/e2e/helpers/mapIdle.js`). An app-side fix — re-place symbols on glyph load — is a possible future improvement.

5/ On live loads, a glyph that arrives after MapLibre's symbol-placement pass can leave its label missing until the next interaction — MapLibre does not re-place symbols when a glyph becomes available. The E2E harness works around this by holding for a sustained glyph-fetch gap, then driving renders to commit any late re-placement before capture (`waitForGlyphsQuiesce` and `renderBurst` in `tests/e2e/helpers/mapIdle.js`, via `waitForMapPainted`). An app-side fix — re-place symbols on glyph load — is a possible future improvement.

6/ **[FIXED]** E2E capture residual: the committed matrix could drift between byte variants across runs — first a sub-perceptual sub-pixel variant (anti-aliasing in the attribution-chip text) that JPEG's DCT smeared across a whole 8×8 block, then a rarer per-launch SwiftShader rasterisation variant (order-nondeterministic parallel rasterisation of overlapping antialiased line fragments, 8-bit source-over rounding) producing sub-level pixel differences. Fixed in two steps: the committed matrix moved from JPEG to lossless PNG — removing the DCT amplification, so a genuine flip shows as a real pixel change rather than a block-sized one — and SwiftShader was forced single-threaded via `SwiftShader.ini` (`[Processor] ThreadCount=1`, written by `tests/e2e/helpers/determinismSetup.js`), which serialises rasterisation and makes captures run-to-run stable in practice (versus an unpinned baseline that intermittently hit the variant); consecutive pinned runs can still differ by a handful of ±1-pixel anti-aliasing flips, which the matrix verifier tolerates and reports. The earlier settle hardening (`fadeDuration: 0` test gate, the active render-then-compare capture loop, glyph/quiet waits) remains. Test-capture artefact only, no app-code impact. See `docs/9.testing.md` (Screenshot determinism).

7/ **[FIXED]** Hitting Random while in follow mode snaps the user back to their current position. Clicking Random now claims the map first: the per-instance action layer stops every other active mode as a hand-off before the camera moves. Follow is owned by locate, so a hand-off returns the chip to Located while the geolocation watcher, position, compass listener and markers stay live. The follow camera releases view suppression without persisting its pose, so the synchronous random fit is the move that reaches the URL hash and storage instead of being re-asserted by the follow camera. On compact layouts the Info pane also closes before the fit; on desktop it stays open.
