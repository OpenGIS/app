# Routes — GPX import and navigation

The Routes feature imports GPX files, renders each route as a LineString on the map, and provides minimal offline navigation via a GPS position marker. Like Recordings, it is a panel-only feature: its panel is registered with `addPanel` and it ships no corner control chip — a chip is optional feature UI, not a requirement.

---

## Overview

Routes is the import counterpart to the Recordings feature: recordings export GPX, routes consume it. A route is stored as a list of `{ lat, lng }` points, rendered through `useGeoJSON`, and persisted in `localStorage`.

| File                                                                            | Purpose                                        |
| ------------------------------------------------------------------------------- | ---------------------------------------------- |
| [`src/features/routes/index.js`](../src/features/routes/index.js)               | Feature object, storage, rendering, navigation |
| [`src/features/routes/gpx.js`](../src/features/routes/gpx.js)                   | Pure, dependency-free GPX parser               |
| [`src/features/routes/RoutesPanel.vue`](../src/features/routes/RoutesPanel.vue) | Side panel UI                                  |
| [`src/utils/geo.js`](../src/utils/geo.js)                                       | Shared geo helpers (also used by Recordings)   |

Registered in [`src/main.js:112`](../src/main.js#L112) after `OfflineFeature`. The panel is registered via `addPanel` ([`index.js:158`](../src/features/routes/index.js#L158)) and appears as a tab in the side panel navigation — there is no corner control chip.

## Storage

Routes are stored as a plain array under the standard instance-scoped key:

```
ogis_routes_{instanceId}
```

```js
const routes = useStorage("routes", []); // src/features/routes/index.js:19
```

Each route object:

```js
{
  id: "m1abc2d",        // Date.now().toString(36) + random suffix
  name: "Morning Loop", // GPX <name>, the filename minus .gpx, or the translated default
  type: "trk" | "rte",  // source element type
  points: [{ lat: 51.5074, lng: -0.1278 }, ...],
  distance: 1234.5,     // metres, computed at import via totalDistance()
}
```

On install the feature re-renders all persisted routes (`renderAll()`, [`index.js:143`](../src/features/routes/index.js#L143)) so routes survive a reload.

## GPX parser

`parseGPX(xml, fallbackName = "Route")` ([`src/features/routes/gpx.js:14`](../src/features/routes/gpx.js#L14)) is a pure, dependency-free parser built on the browser's native `DOMParser`. It returns an array of `{ name, points, type }` objects.

```js
import { parseGPX } from "@/features/routes/gpx.js";

const routes = parseGPX(`<gpx version="1.1">
  <trk><name>Morning Loop</name><trkseg>
    <trkpt lat="51.5074" lon="-0.1278"/>
    <trkpt lat="51.512" lon="-0.1225"/>
  </trkseg></trk>
</gpx>`);
// → [{ name: "Morning Loop", type: "trk", points: [{ lat: 51.5074, lng: -0.1278 }, ...] }]
```

Behaviour:

- Handles `<trk><trkseg><trkpt>` and `<rte><rtept>`; matches on `localName`, so namespaced GPX documents parse correctly.
- Skips points with missing or non-numeric `lat`/`lon`; a route needs at least 2 valid points to be kept.
- Uses the first `<name>` child, falling back to `fallbackName` when absent or blank — the feature passes the filename minus `.gpx`, or the translated `panel.routes.defaultName`.
- Throws errors carrying stable sentinel codes: `invalid-gpx` for malformed XML and `no-routes` when nothing usable remains; the panel maps them to translated messages (see [Locale — Message codes and sentinel errors](./7.locale.md#message-codes-and-sentinel-errors)).
- `<wpt>` waypoints are ignored in v1.

## Rendering

Each route is rendered as a `LineString` via `useGeoJSON` ([`index.js:29`](../src/features/routes/index.js#L29)):

```js
geoJSON.setFeature({
  type: "Feature",
  id: `routes-route-${route.id}`,
  geometry: {
    type: "LineString",
    coordinates: [
      [-0.1278, 51.5074],
      [-0.1225, 51.512],
    ],
  },
  properties: { "ogis.width": 4, "ogis.opacity": 0.85 },
});
```

No `ogis.color` is set, so each route gets a persistent auto-assigned colour from `useGeoJSON` (see [GeoJSON](./6.geojson.md)). All routes are always visible — there is no per-route visibility toggle.

`showOnMap(id)` ([`index.js:106`](../src/features/routes/index.js#L106)) calls `claimMap()` — ending any active follow, draw or navigation mode as a hand-off — then fits the map bounds to the route with 40 px padding. See [UI actions and map modes](./5.ui.md#ui-actions-and-map-modes).

## Navigation

`startNavigation(id)` ([`index.js:113`](../src/features/routes/index.js#L113)) claims the map with `navigate` excluded, enters the `navigate` mode, fits the route, then starts a `navigator.geolocation.watchPosition` loop (`enableHighAccuracy: true`, `maximumAge: 2000`) and renders the current position as a blue point marker:

```js
geoJSON.setFeature({
  type: "Feature",
  id: "routes-position",
  geometry: {
    type: "Point",
    coordinates: [pos.coords.longitude, pos.coords.latitude],
  },
  properties: { "ogis.color": "#0d6efd", "ogis.radius": 8 },
});
```

`stopNavigation()` ([`index.js:74`](../src/features/routes/index.js#L74)) clears the watch, removes the marker and ends the `navigate` mode — the Stop button therefore releases the camera for the next action. Deleting the route being navigated also stops navigation ([`index.js:83`](../src/features/routes/index.js#L83)), and the feature's cleanup function stops it on app destroy.

Navigation is deliberately minimal: it is a GPS position marker over the route geometry — no progress, distance-to-end, or off-route calculations. It works offline because it is entirely client-side (GPS + stored geometry); the map background still relies on the [Offline](./12.offline.md) tile download.

## Shared geo helpers

`src/utils/geo.js` holds the distance/format helpers shared by Recordings and Routes:

| Function                                                 | Returns                                                            |
| -------------------------------------------------------- | ------------------------------------------------------------------ |
| `haversine(a, b)`                                        | Great-circle distance between two `{ lat, lng }` points, in metres |
| `totalDistance(points)`                                  | Sum of haversine segments, in metres                               |
| `formatDuration(ms)`                                     | `H:MM:SS` or `M:SS`                                                |
| `formatDistance(metres, isMetric = true, locale = "en")` | `km`/`m` or `mi`/`ft` string, formatted for `locale`               |

Recordings imports all four and re-exports `formatDuration`/`formatDistance` for its panel ([`src/features/recordings/index.js:15`](../src/features/recordings/index.js#L15)); Routes imports `totalDistance` and `formatDistance` ([`index.js:4`](../src/features/routes/index.js#L4)).

## Panel UI

`RoutesPanel.vue` provides:

- a file input accepting `.gpx` / `application/gpx+xml`, multiple files, each imported via `importGPX`
- an error line showing the message mapped from the parser's sentinel code, falling back to the generic `panel.routes.errorImport` message — never the raw error — for unknown errors
- a route list with name, locale-formatted distance, and Show / Navigate-or-Stop / Delete buttons
- a "Navigation active — following GPS position" note while navigating

Every string in the panel resolves through `t()` — `menu.routes` for the tab and heading, `panel.routes.*` for the rest. Import errors surface through the parser's sentinel codes, mapped to `panel.routes.errorInvalidGpx` / `panel.routes.errorNoRoutes` (see [Locale — Message codes and sentinel errors](./7.locale.md#message-codes-and-sentinel-errors)).

## Limitations

- **Storage quota.** Routes are stored as-is in `localStorage` (5 MB per origin); large GPX files may not fit.
- **Waypoints ignored.** `<wpt>` elements are not imported in v1.
- **No visibility toggle.** All routes are always rendered.
- **Minimal navigation.** The position marker has no progress or off-route logic.
- **Offline map background** depends on the Offline feature's downloaded tiles.
