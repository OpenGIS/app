# Features

A feature is a self-contained bundle of logic, a panel, and (optionally) a map-corner control chip. Features are installed from `src/main.js` before the app mounts.

---

## Feature structure

A feature is a plain object with an `install(ctx)` method:

```
src/features/{name}/
  index.js            ← feature object + business logic
  {Name}Button.vue    ← corner control chip (optional)
  {Name}Panel.vue     ← side panel tab (optional)
```

---

## Feature context

`install(ctx)` receives a context object built in `src/main.js`:

```js
{
  app,           // Vue app instance
  instanceId,    // string — for storage scoping
  map,           // shallowRef<Map | null> — reactive map handle
  emitter,       // EventEmitter singleton
  useStorage,    // (namespace, definition) → { state, flush, reset } — pre-scoped persisted state
  useSettings,   // () → OS-derived settings (theme, units); no instanceId, nothing stored
  useLocale,     // () → { locale, mapLanguageTag, formatLocale, t } — translations resolved per instance; nothing stored
  getMap,        // () → MapLibre map instance or null
  onMapReady,    // (cb) → cb({ map, addSource, addLayer }) with auto-cleanup
  on,            // EventEmitter wrappers
  once,
  off,
  emit,
  provide,       // (key, value) → app.provide
  addButton,     // (config) → adds a corner control chip (+ panel tab)
  addPanel,      // (config) → adds a panel tab
}
```

### `addButton(config)`

Registers a control chip in the map's bottom-right corner (and, when a `panel` is supplied, a side-panel tab):

```js
addButton({
  id: "my-feature", // panel tab id — match it in setActivePanel()
  icon: "route", // used when no component is supplied
  position: "bottom-right", // the only rendered position
  component: MyButton, // Vue component rendering an IconButton chip
  panel: {
    title: () => t("menu.myFeature"), // a string, or a thunk for translations
    component: MyPanel,
  },
});
```

- Buttons are rendered by the corner-controls overlay ([`src/components/ui/controls.vue:60`](../src/components/ui/controls.vue#L60)); a button without `position: 'bottom-right'` is not rendered.
- With a `panel`, the button also becomes a panel tab. A plain (icon/label) button opens that panel on click; a `component` button handles its own click and can call `setActivePanel()` / `openPanel()` itself.
- `id` should match the panel tab id used with `setActivePanel()`.

### `addPanel(config)`

Registers a panel-only tab in the side panel navigation (`.panel-nav`) — no corner button. The config is pushed into the `navigatorPanels` registry ([`src/main.js:134`](../src/main.js#L134)) and rendered as a tab via `panelTabs` ([`src/components/ui/panels.vue:42`](../src/components/ui/panels.vue#L42)):

```js
addPanel({
  id: "my-feature",
  icon: "cloud-arrow-up",
  title: () => t("menu.myFeature"), // a string, or a thunk for translations
  component: MyPanel,
});
```

A `title` may be a plain string or a thunk returning one. Features use a thunk that calls `t()` so the tab label re-evaluates when the locale changes — the registry resolves the label at render time ([`panels.vue:25`](../src/components/ui/panels.vue#L25)).

### `onMapReady(callback)`

Registers a callback that fires once the MapLibre map is ready. The callback receives `{ map, addSource, addLayer }`. Sources and layers added via these helpers are automatically removed on app destroy:

```js
onMapReady(({ map, addSource, addLayer }) => {
  addSource('my-source', { type: 'geojson', data: featureCollection });
  addLayer({ id: 'my-layer', type: 'circle', source: 'my-source', paint: { ... } });
});
```

The callback is guarded at call time: a throw is reported with `{ source: "map-ready" }` and cannot break `map:ready` delivery to other features. `installFeature` also tracks the registration's disposer, so a feature that fails during install does not leave a pending map-ready callback behind. The callback runs once.

## Persistence and restore

Features persist state through `ctx.useStorage(namespace, definition)`, a thin wrapper around [`usePersistedState`](../src/resilience/persistedState.js):

```js
const stored = useStorage("my-feature", {
  version: 1,
  defaults: { items: [] },
  hydrate: hydrateMyFeature,
}).state;
```

- Give the store a namespace, a current `version` and explicit `defaults`.
- Supply a `hydrate` when stored data can be legacy, malformed or partly untrustworthy. Repair field-level problems; throw to reject an uninterpretable top-level value. See [State and resilience — Hydration and validation](./16.state-and-resilience.md#hydration-and-validation).
- Bump `version` when the stored shape changes incompatibly, and handle earlier versions in the hydrator.
- Run side-effecting restores after mount; a pure render-only restore (such as route visibility) may run during install. A restore must never prompt or claim the camera.
- Make restore failure silent and non-throwing. If another feature must wait for your restore, expose a promise (as `useLocate` does with `restoreComplete`).
- Persist intent, not derived values (distance, speed, live pose while a controller owns the camera).
- Only opt into `crossTab` when applying an external write is safe and cannot echo.

Full contract, store inventory and worked examples: [State and resilience](./16.state-and-resilience.md).

## Map modes

A feature that takes the camera for longer than a single move — following, drawing, navigating — registers a mode with [`useActions`](../src/composables/useActions.js): an `active` ref plus a synchronous, idempotent `stop({ handoff })`. A feature that fits the camera for a one-shot action calls `claimMap()` before the fit, or expresses the action as a descriptor in [`src/actions.js`](../src/actions.js) and runs it through `perform`.

A hand-off stop (`{ handoff: true }`) releases the camera and any view-persistence suppression without persisting, so the incoming action's camera move is the one that persists; a full stop tears the mode down and may persist once. See [UI — UI actions and map modes](./5.ui.md#ui-actions-and-map-modes).

## Registering a feature

In `src/main.js`, import and install the feature before `app.mount()` through `installFeature`:

```js
import { RecordingsFeature } from "./features/recordings/index.js";
import { installFeature } from "./resilience/boot.js";

installFeature("recordings", RecordingsFeature, featureCtx);
```

`installFeature` isolates the install: registrations made through `addButton`, `addPanel`, `on`, `once` and `onMapReady` are tracked, and a throw rolls them back in reverse order before the failure is reported. The other features still install and the app still mounts. `provide` cannot be rolled back. See [State and resilience — Feature install isolation](./16.state-and-resilience.md#feature-install-isolation).

## Recordings — worked example

The Recordings feature (`src/features/recordings/`) records GPS tracks using the
Geolocation API, renders them live on the map via `useGeoJSON`, saves them to
`localStorage` as versioned track documents, and shares them as GPX or GeoJSON.
All controls live in its side panel.

### Feature object (`index.js`)

```js
export const RecordingsFeature = {
  install({
    useStorage,
    useSettings,
    getMap,
    instanceId,
    provide,
    addPanel,
    useLocale,
  }) {
    const stored = useStorage("recordings", {
      version: 1,
      defaults: { saved: [], active: null },
      hydrate: hydrateRecordings,
    }).state;
    const { isMetric } = useSettings();
    const { t } = useLocale();
    const geoJSON = useGeoJSON(instanceId);

    // ... colour assignment, state, GPS watch, GeoJSON rendering ...

    addPanel({
      id: "record",
      icon: "route",
      title: () => t("menu.recordings"),
      component: RecordingsPanel,
    });

    provide("recordings", {
      state,
      elapsed,
      distance,
      isMetric,
      start,
      pause,
      resume,
      discard,
      save,
      shareRecording,
      toggleVisibility,
      isVisible,
      hideOnMap,
      showOnMap,
      deleteRecording,
    });
  },
};
```

### GeoJSON integration

The active recording is rendered as a live `LineString` using green
(`#39d353`) via `useGeoJSON`:

```js
geoJSON.setFeature({
  type: "Feature",
  id: "recordings-active-track",
  geometry: { type: "LineString", coordinates: coords },
  properties: {
    "ogis.color": "#39d353",
    "ogis.width": 3,
    "ogis.opacity": 0.85,
    "ogis.direction": true,
  },
});
```

`ogis.direction: true` adds the static direction chevrons described in
[GeoJSON](./6.geojson.md#direction-chevrons). The active track uses a fixed
feature ID and stays separate from any saved recording shown on the map; saved
recordings render under `recordings-saved-{id}`, with their own colour and
waypoint features.

### Storage

Active recording and saved documents are persisted under
`ogis_recordings_{instanceId}` as a versioned envelope:

```js
const stored = useStorage("recordings", {
  version: 1,
  defaults: { saved: [], active: null },
  hydrate: hydrateRecordings,
}).state;
```

`hydrateRecordings` migrates legacy saved/active shapes, sanitises every
document and point, and drops unusable entries. Saved recordings are v2 track documents
([`src/features/recordings/index.js:195`](../src/features/recordings/index.js#L195)):

```js
{
  v: 2,
  id: "m1abc2d-x9k2p1q7",
  kind: "recording",
  name: null,
  gpxType: null,
  createdAt: 1760000000000,
  source: { format: "gps" },
  segments: [{ points: [{ lat: 48.949011, lng: -55.652574, t: 1760000000000 }] }],
  waypoints: [],
  duration: 5400000,
  color: "#2ecc71",
}
```

On hydrate, legacy saved and active shapes are migrated with
`migrateRecording` / `migrateActiveRecording` and then passed through
`sanitiseTrackDocument`; the storage key is unchanged.
Points keep optional elevation and timestamps through the v2 model — captured
GPS points always carry `t`, while elevation is present only when supplied by
the source or carried over from a migrated document. The `saved` array keeps
insertion order (new recordings are appended); the panel lists them newest first
by `createdAt`, falling back to descending ID order.

### Sharing and export

`shareRecording(recording, "gpx" | "geojson")`
([`index.js:287`](../src/features/recordings/index.js#L287)) projects the v2
document with `toGPX` or `toGeoJSON`, names it with `trackFilename`, and calls
`shareFile` — the Web Share API when available, otherwise a download. GPX uses
the custom writer described in [Tracks — Export](./15.tracks.md#export);
GeoJSON includes elevation as the third ordinate and per-point times in
`properties.coordinateProperties.times`.

### Components

The feature is panel-only — it registers no corner chip.

- **`RecordingsPanel.vue`** — hosts the whole recording UI: the idle **Start recording** control (`#recordings-start-button`, behind the same first-use permission request as Locate), the active Pause/Resume, Save and Discard controls, and the saved-recordings list with Show/Hide, a Share menu (GPX/GeoJSON) and Delete behind a native `window.confirm`; injects `recordings` from `provide`
- **Menu-chip status dot** — while a track is active the feature raises the generic `menuBadge` signal (`useUI(instanceId).setMenuBadge("recording" | "paused")`), so the always-mounted menu chip shows the state even when the panel is closed (see [UI — `useUI`](./5.ui.md)). Routes publishes the separate `menuNavigation` signal (`setMenuNavigation`) for follow-mode navigation state, rendered by the core top-centre navigation control rather than the menu chip (see [Routes — Navigation](./11.routes.md#navigation))

### State shape

The in-memory runtime state is:

```js
{
  isRecording: false,
  isPaused: false,
  points: [],          // active track points: [{ lat, lng, t }]
  startTime: null,     // ms timestamp
  saved: [],           // v2 recording documents (see Storage)
}
```

The persisted active recording is a sanitised v2 document with a single
segment, so a crash mid-recording can restore the paused line; saved rows
compute distance with `documentDistance` rather than a stored value. Restoring
an interrupted recording does not restart the GPS watch.

## Adding a new feature

1. Create `src/features/{name}/index.js` with an `install(ctx)` method
2. Create `src/features/{name}/{Name}Button.vue` and `{Name}Panel.vue` as needed
3. Register in `src/main.js` through `installFeature("name", MyFeature, featureCtx)`
4. Persist state with `ctx.useStorage(namespace, { version, defaults, hydrate })`; restore silently after mount, never from a prompt or a camera claim (see [Persistence and restore](#persistence-and-restore))
5. Localise: render every user-visible string through `t()` (destructure `useLocale` from the context) and keep logic layers language-free, emitting stable sentinel codes for the panel to map (see [Locale](./7.locale.md#message-codes-and-sentinel-errors))
6. Add unit tests in `tests/unit/` for pure logic
7. Add an E2E spec in `tests/e2e/features/{name}.spec.js` for integration
