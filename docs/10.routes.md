# Routes — GPX import and navigation

The Routes feature imports GPX files, renders each route as a LineString on the map, and provides minimal offline navigation via a GPS position marker. It is a panel-only feature — no corner control chip.

---

## Overview

Routes is the import counterpart to the Recordings feature: recordings export GPX, routes consume it. A route is stored as a list of `{ lat, lng }` points, rendered through `useGeoJSON`, and persisted in `localStorage`.

| File                                                                            | Purpose                                        |
| ------------------------------------------------------------------------------- | ---------------------------------------------- |
| [`src/features/routes/index.js`](../src/features/routes/index.js)               | Feature object, storage, rendering, navigation |
| [`src/features/routes/gpx.js`](../src/features/routes/gpx.js)                   | Pure, dependency-free GPX parser               |

## Storage

Routes are stored as a plain array under the standard instance-scoped key:

```
onrte_routes_{instanceId}
```

```js
const routes = useStorage("routes", []); // src/features/routes/index.js:10
```

Each route object:

```js
{
  id: "m1abc2d",        // Date.now().toString(36) + random suffix
  name: "Morning Loop", // GPX <name>, or the filename minus .gpx, or "Route"
  type: "trk" | "rte",  // source element type
  points: [{ lat: 50.6539, lng: -128.0094 }, ...],
  distance: 1234.5,     // metres, computed at import via totalDistance()
}
```

On install the feature re-renders all persisted routes (`renderAll()`, [`index.js:116`](../src/features/routes/index.js#L116)) so routes survive a reload.

## GPX parser

`parseGPX(xml, fallbackName = "Route")` ([`src/features/routes/gpx.js:14`](../src/features/routes/gpx.js#L14)) is a pure, dependency-free parser built on the browser's native `DOMParser`. It returns an array of `{ name, points, type }` objects.

```js
import { parseGPX } from "@/features/routes/gpx.js";

const routes = parseGPX(`<gpx version="1.1">
  <trk><name>Morning Loop</name><trkseg>
    <trkpt lat="50.6539" lon="-128.0094"/>
    <trkpt lat="50.66" lon="-128.02"/>
  </trkseg></trk>
</gpx>`);
// → [{ name: "Morning Loop", type: "trk", points: [{ lat: 50.6539, lng: -128.0094 }, ...] }]
```

Behaviour:

- Handles `<trk><trkseg><trkpt>` and `<rte><rtept>`; matches on `localName`, so namespaced GPX documents parse correctly.
- Skips points with missing or non-numeric `lat`/`lon`; a route needs at least 2 valid points to be kept.
- Uses the first `<name>` child, falling back to `fallbackName` when absent or blank.
- Throws `Error("Invalid GPX file")` for malformed XML and `Error("No routes found in GPX file")` when nothing usable remains.
- `<wpt>` waypoints are ignored in v1.

## Rendering

Each route is rendered as a `LineString` via `useGeoJSON` ([`index.js:18`](../src/features/routes/index.js#L18)):

```js
geoJSON.setFeature({
  type: "Feature",
  id: `routes-route-${route.id}`,
  geometry: {
    type: "LineString",
    coordinates: [
      [-128.0094, 50.6539],
      [-128.02, 50.66],
    ],
  },
  properties: { "onrte.width": 4, "onrte.opacity": 0.85 },
});
```

No `onrte.color` is set, so each route gets a persistent auto-assigned colour from `useGeoJSON` (see [GeoJSON](./5.geojson.md)). All routes are always visible — there is no per-route visibility toggle.

`showOnMap(id)` ([`index.js:76`](../src/features/routes/index.js#L76)) fits the map bounds to the route with 40 px padding.

## Navigation

`startNavigation(id)` ([`index.js:94`](../src/features/routes/index.js#L94)) starts a `navigator.geolocation.watchPosition` loop (`enableHighAccuracy: true`, `maximumAge: 2000`) and renders the current position as a blue point marker:

```js
geoJSON.setFeature({
  type: "Feature",
  id: "routes-position",
  geometry: {
    type: "Point",
    coordinates: [pos.coords.longitude, pos.coords.latitude],
  },
  properties: { "onrte.color": "#0d6efd", "onrte.radius": 8 },
});
```

`stopNavigation()` ([`index.js:60`](../src/features/routes/index.js#L60)) clears the watch and removes the marker. Deleting the route being navigated also stops navigation ([`index.js:73`](../src/features/routes/index.js#L73)), and the feature's cleanup function stops it on app destroy.

Navigation is deliberately minimal: it is a GPS position marker over the route geometry — no progress, distance-to-end, or off-route calculations. It works offline because it is entirely client-side (GPS + stored geometry); the map background still relies on the [Offline](./10.offline.md) tile download.

## Shared geo helpers

`src/utils/geo.js` holds the distance/format helpers shared by Recordings and Routes:

| Function                                  | Returns                                                            |
| ----------------------------------------- | ------------------------------------------------------------------ |
| `haversine(a, b)`                         | Great-circle distance between two `{ lat, lng }` points, in metres |
| `totalDistance(points)`                   | Sum of haversine segments, in metres                               |
| `formatDuration(ms)`                      | `H:MM:SS` or `M:SS`                                                |
| `formatDistance(metres, isMetric = true)` | `km`/`m` or `mi`/`ft` string                                       |

Recordings imports all four and re-exports `formatDuration`/`formatDistance` for its panel ([`src/features/recordings/index.js:14`](../src/features/recordings/index.js#L14)); Routes imports `totalDistance` and `formatDistance` ([`index.js:4`](../src/features/routes/index.js#L4)).

## Panel UI

`RoutesPanel.vue` provides:

- a file input accepting `.gpx` / `application/gpx+xml`, multiple files, each imported via `importGPX`
- an error line showing the parser's message on failure
- a route list with name, formatted distance, and Show / Navigate-or-Stop / Delete buttons
- a "Navigation active — following GPS position" note while navigating

Strings are hard-coded English — feature panels are not localised, matching the Recordings and Offline precedent.

---

## Limitations

- **Storage quota.** Routes are stored as-is in `localStorage` (5 MB per origin); large GPX files may not fit.
- **Waypoints ignored.** `<wpt>` elements are not imported in v1.
- **No visibility toggle.** All routes are always rendered.
- **Minimal navigation.** The position marker has no progress or off-route logic.
- **Offline map background** depends on the Offline feature's downloaded tiles.
