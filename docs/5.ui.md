# UI — `useUI`

`useUI` manages all application UI state: responsive breakpoints and the side panel. The map chrome is two components — the corner controls overlay (`src/components/ui/controls.vue`) and the side panel (`src/components/ui/panels.vue`). There is no top navigation bar. Camera-taking UI is arbitrated separately by `useActions` (see [UI actions and map modes](#ui-actions-and-map-modes)).

---

## Usage

```js
import { useUI } from "@/composables/useUI.js";

const { isDesktop, isPanelVisible, setActivePanel, openPanel } = useUI();
```

State is cached per instance in a module-level `Map` keyed by `instanceId` (see [Instances](./3.instances.md)).

---

## Responsive breakpoints

`useUI` tracks `window.innerWidth` via a resize listener and exposes three computed flags.

| Computed    | Type      | Condition               |
| ----------- | --------- | ----------------------- |
| `isDesktop` | `boolean` | `width >= 992px`        |
| `isTablet`  | `boolean` | `768px ≤ width < 992px` |
| `isMobile`  | `boolean` | `width < 768px`         |

The corner chips render at every breakpoint; only the panel behaviour changes with width.

## Corner controls

[`src/components/ui/controls.vue`](../src/components/ui/controls.vue) renders a full-screen, click-through overlay (`.ogis-controls`) with five corner clusters (`.ogis-corner--tl` / `--tc` / `--tr` / `--br` / `--bl`):

| Corner       | Control                                                                           | ID                    |
| ------------ | --------------------------------------------------------------------------------- | --------------------- |
| Top-left     | Menu chip — toggles the side panel                                                | `#menu-button`        |
| Top-centre   | Navigation status — non-interactive route readout                                 | —                     |
| Top-right    | Locate chip (GPS cycle)                                                           | `#locate-button`      |
| Bottom-right | Feature buttons registered with `position: 'bottom-right'` (none installed today) | feature-defined       |
| Bottom-left  | Attribution chip — toggles the Info pane                                          | `#attribution-button` |

- Every control is a **chip** — the `chip` variant of `IconButton` (`.icon-btn--chip`), a 72 px frosted-glass circle with the icon above a short monospace uppercase label. The expanded attribution chip is the exception: it renders as a wide credits pill and joins the circles only while collapsed.
- Chip labels are fitted to the button at runtime (see [Fitted chip labels](#fitted-chip-labels--usefittext)). The class defaults live in [Theme](./8.theme.md#corner-controls-ogis-controls); each mount can override the levers per chip through the chip-only `IconButton` props (`iconSize`, `iconGap`, `labelMin`, `labelMax`, `labelTarget`).
- Features register corner buttons with `addButton({ …, position: 'bottom-right' })`; the `--br` cluster renders only when one does, and no feature registers one today. Buttons without that position are not rendered ([`controls.vue:27`](../src/components/ui/controls.vue#L27)).
- The **menu chip** carries a recording badge (`.ogis-menu-badge`) when a feature raises the generic `menuBadge` signal: Recordings sets it to `recording` (red, `data-state="recording"`) or `paused` (orange, `data-state="paused"`) while a track is active — whether or not the panel is open. The badge is decorative (`pointer-events: none` and `aria-hidden`), so clicking the chip anywhere still opens the menu. The signal lives on `useUI` ([`setMenuBadge`](../src/composables/useUI.js#L106)); the core chrome stays feature-agnostic.
- The **top-centre navigation control** (`.ogis-nav-control`) renders while a feature raises the separate `menuNavigation` signal, keeping route status clear of the chip row. It is a full-size, non-interactive readout: off route it shows a direction arrow rotated relative to the map bearing, the distance and an `Off route` caption; on route a check and `On route`; and before the first fix a dimmed arrow and `Locating…`. While off route within 1 km it also draws the green dashed `.ogis-nav-connector` polyline from the locate marker to the nearest point on the route (see [Routes — Navigation](./11.routes.md#navigation)). Both `menuBadge` and `menuNavigation` live on `useUI` ([`setMenuBadge`](../src/composables/useUI.js#L106), [`setMenuNavigation`](../src/composables/useUI.js#L110)); the core chrome stays feature-agnostic. The control is `pointer-events: none`; its exact status is carried by its accessible label.
- The **locate chip** (`#locate-button`) cycles Locate → Located → Following → stopped; a geolocation error switches the label to Error and re-opens the error modal on click. Following hands the camera to the follow driver ([Map — view orientation](./4.map.md#view-orientation)): the chip still reads Following while a user gesture temporarily suspends the camera's return. A map action that claims the camera — Random, Improve, showing a route, recording or region, or starting a draw — hands Following back to Located: tracking continues, but the follow camera releases the map so the action's move takes effect (see [Hand-off semantics](#hand-off-semantics)). Route navigation is the exception: Navigate enters the `navigate` mode alongside follow, closes the pane so the top-centre card is unobstructed, and the chip keeps reading Following (see [Routes — Navigation](./11.routes.md#navigation)). Its colour reflects the mode alone — there is deliberately no `:hover` tint (pinned by E2E on pointer and touch); labels come from the `locate.button.*` keys (see [Locale](./7.locale.md)).

- On desktop the overlay mirrors the panel shift (`.ogis-controls.panel-open`), keeping controls over the visible map.
- Each corner cluster adds the device's safe-area insets to its padding, so chips clear notches, status bars and the home indicator (see [Theme](./8.theme.md)).
- The **attribution chip** shows the live style attribution, assembled by `buildAttribution` ([`src/utils/attribution.js`](../src/utils/attribution.js)) and exposed reactively by [`useAttribution`](../src/composables/useAttribution.js). It expands as the credits pill while the Info pane is closed — on load, before any drag — and collapses to a circle — the info icon plus a fitted label from `menu.info` — while the Info pane is open, because the pane's sticky footer already shows the attribution; closing the pane expands it again. Desktop auto-opens the Info pane on load, so the chip starts collapsed there. The first map drag latches it collapsed permanently (MapLibre parity). The state is a computed in [`useAttribution`](../src/composables/useAttribution.js) and is mirrored onto `.ogis-root` as `data-attrib-collapsed`. Clicking it toggles the Info pane. MapLibre's built-in attribution control is disabled (`attributionControl: false` in [`src/defaults/maplibre.js`](../src/defaults/maplibre.js)).

## Fitted chip labels — `useFitText`

[`useFitText`](../src/composables/useFitText.js) fits a single-line label to its button by scaling the label's font-size. It measures the label at the maximum size, then scales it so the rendered width aims at a target fraction of the button width, clamped between `min` and `max`. Only the label's inline `font-size` is touched — text and DOM stay untouched.

- Levers are read from CSS custom properties on the label (inherited from the chip), so they can be tuned in one place: `--ogis-chip-label-min` and `--ogis-chip-label-max` (px), and `--ogis-chip-label-target` (a fraction or percentage). The `.icon-btn--chip` defaults live in [Theme](./8.theme.md#corner-controls-ogis-controls); the chip-only `IconButton` props (`labelMin`, `labelMax`, `labelTarget` — and for the other chip levers `iconSize` and `iconGap`) render inline custom-property overrides on the button.
- Re-fits when the label text changes and whenever the button resizes (`ResizeObserver`, disconnected on unmount). An `enabled` option gates it: `IconButton` fits only in chip mode, and the attribution chip only while collapsed, re-fitting on the next tick once the collapsed label is in the DOM.
- Defensive outside the browser — without `getComputedStyle` it no-ops, and missing custom properties fall back to built-in defaults.

## Panel

The side column hosts one of two independent panes, tracked by `visiblePane` (`null | 'menu' | 'info'`):

- **Menu pane** (`'menu'`) — the tabbed menu. The menu is feature-only: tabs come from installed features. Features add tabs with a corner control via `addButton({ panel: { ... } })`, or register a panel-only tab (no corner button) via `addPanel({ id, icon, title, component })` — pushed into the `navigatorPanels` registry and rendered in `.panel-nav` via `panelTabs` ([`src/components/ui/panels.vue:42`](../src/components/ui/panels.vue#L42)). The core features all use `addPanel`; with them installed the tab strip is Recordings, Offline Maps and Routes, and the default active tab is the first feature tab (`record`).
- **Info pane** (`'info'`) — the Info panel ([`src/components/panels/info.vue`](../src/components/panels/info.vue)), rendered directly without the tab strip. It merges the former View, About and Privacy panels: an unheaded share block that leads the panel — the canonical share URL in a read-only textarea, a Share button that is a real `<a>` to that URL (`navigator.share` where available, otherwise a clipboard copy with a transient "Copied!" state), and an actions row — Improve (resets the camera north-up, then opens an OpenStreetMap note at the live centre and zoom in a new tab) and Random (fits a random country in-app — no navigation/full reload; `?country=random` remains a supported entry/deep link — see [Cold-start country focus](./4.map.md#cold-start-country-focus)); an About branding row (`.ogis-about-section`) — the "Free, private & Open Source" tagline (linking to the OpenGIS GitHub repo) beside the OGIS logo (`.ogis-about-logo`); and one pinned, unheaded footer (`.ogis-info-footer`) holding the Privacy and Attribution sections, which content scrolls behind. The Privacy section (`.ogis-privacy-section`) is a compact bar: a native `<details>` whose summary shows the heading, a two-line-clamped trust line and a CSS-generated `+` / `−` glyph, expanding to the two sub-sections (on-device storage and third-party sources) in a height-capped, internally scrolling body. The Attribution section (`.ogis-attribution-section`) sits below it inside the same footer.

The panel reuses Bootstrap's offcanvas CSS classes, but the app ships no Bootstrap JS: the panel's `show` class is bound to `isPanelVisible` ([`panels.vue:124`](../src/components/ui/panels.vue#L124)) and the mobile dismiss backdrop is a Vue-rendered `v-if` element ([`panels.vue:173`](../src/components/ui/panels.vue#L173)).

Both panes share one offcanvas root, marked as an ARIA `region` and given a stable accessible name from a visually hidden span bound to `nav.menu` (`aria-labelledby="ogis-panel-label"`).

On desktop (`isDesktop`), the app opens the **Info pane** automatically on load. Mobile opens no pane on load; the menu pane is only opened by the user (menu chip or a feature button). On small screens the panel is capped at `min(340px, calc(100vw - 4rem))` so a tappable strip of the dismiss backdrop stays visible beside it; tapping that strip calls `closePanel()`. Desktop keeps the full 340 px width.

The two panes are separate: opening the Info pane never changes the menu's active tab, so switching between them preserves your position in the menu. `activePanel` only ever holds a menu tab id.

### `setActivePanel(id)` — switch the menu's active tab

```js
setActivePanel("record");
```

Emits a `panel:change` event. Only meaningful for the menu pane — never set to `'info'`. If the id is not among the available tabs (stale session, feature not installed), the pane falls back to the first available tab.

### `openPanel()` / `openInfo()` — open a pane

```js
setActivePanel("record");
openPanel(); // menu pane
openInfo(); // info pane
```

Both set `isPanelExpanded` to `true`.

### `togglePanel()` / `toggleInfo()` / `closePanel()`

- `togglePanel()` — toggles the menu pane (if the info pane is showing, switches to the menu)
- `toggleInfo()` — toggles the info pane (if the menu pane is showing, switches to info)
- `closePanel()` — closes whichever pane is visible, without changing the active tab

## UI actions and map modes

Map-taking UI must reconcile state before it moves the camera. A sustained mode — following, drawing a region, navigating a route — owns the camera while it runs. A one-shot action such as Random must first take that ownership away; otherwise the outgoing mode re-asserts its pose and suppresses the action's view persistence. [`useActions`](../src/composables/useActions.js) is the per-instance registry that arbitrates this.

Actions are plain descriptors in [`src/actions.js`](../src/actions.js). `perform` resolves the map, evaluates `requires`, claims the map when `needsMap`, dismisses the pane when `dismissPanel`, then runs — in that order. It returns `false` without claiming or dismissing when a `needsMap` action has no map, or when a precondition fails.

`useActions(explicitInstanceId?)` resolves the instance via `inject('ogisAppId')` when no id is passed and caches its registry per instance, like `useUI` and `useLocate`.

### Action registry API

| Member         | Signature                              | Behaviour                                                                                                                                                                                                                                                                                        |
| -------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `registerMode` | `(id, { active, stop }) => unregister` | Registers a sustained mode. `active` is a `Ref<boolean>`; `stop({ handoff })` is synchronous and idempotent. Registering the same id replaces that entry in place, and the returned unregister only removes its own registration.                                                                |
| `activeModes`  | `ComputedRef<string[]>`                | IDs of active modes, in registration order.                                                                                                                                                                                                                                                      |
| `claimMap`     | `({ except }?)`                        | Stops every active mode except `except` with `{ handoff: true }`.                                                                                                                                                                                                                                |
| `dismissPanel` | `()`                                   | Closes the side pane below the desktop breakpoint (`<992px`); a no-op on desktop.                                                                                                                                                                                                                |
| `perform`      | `(action, payload?) => boolean`        | Resolves the map, evaluates `requires`, claims the map when `needsMap`, dismisses the pane when `dismissPanel`, then calls `run({ map, instanceId, orientView }, payload)`. A missing map on a `needsMap` action, or a failed precondition, returns `false` before any mode or UI state changes. |

### Action descriptors

| Field                                           | Purpose                                                                                                                                   |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `needsMap`                                      | Requires a resolved map and claims the camera from every other active mode.                                                               |
| `dismissPanel`                                  | Closes the pane below the desktop breakpoint before running.                                                                              |
| `requires({ map, instanceId, orientView })`     | Precondition; `false` aborts before any mode stops or the UI changes.                                                                     |
| `except`                                        | Mode id excluded from the claim — used when the action belongs to that mode (Routes navigation calls `claimMap({ except: 'navigate' })`). |
| `run({ map, instanceId, orientView }, payload)` | The action itself.                                                                                                                        |

### Registered modes

| Mode       | Owner          | Active while           | Stop behaviour                                                                                                                                                                                                                                                                                                 |
| ---------- | -------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `follow`   | `useLocate`    | `mode === 'following'` | A hand-off calls `endFollowing({ persist: false })`: the mode returns to `active` (the chip reads Located), the geolocation watcher, position, compass listener and markers stay, and the follow camera stops without persisting its pose. A full locate `stop()` still tears tracking down and persists once. |
| `draw`     | `OfflinePanel` | the draw is running    | Stops the draw. A hand-off stop does not reopen the pane; a normal completed draw reopens it below the desktop breakpoint.                                                                                                                                                                                     |
| `navigate` | Routes install | `navigating !== null`  | Calls `stopNavigation()`.                                                                                                                                                                                                                                                                                      |

### Hand-off semantics

`claimMap` stops modes with `{ handoff: true }`. A mode must treat that as "release the camera, keep the user's session": stop its per-frame or gesture control, release any persistence suppression, and leave user-visible state alone. It must **not** persist its final pose — the incoming action's camera move is the one that reaches the URL hash and storage. Modes must be idempotent, because a claim can arrive while one is already stopping.

A full stop is different: it tears the mode down, persists once where applicable, and may restore UI state (the offline draw reopens its pane after a completed selection).

### Built-in actions

- **Random** (`actions.random`) — `needsMap` and `dismissPanel`: claims the map, ending every active mode, then fits a random country. On compact layouts the pane closes first so the fitted country is unobstructed; on desktop it stays open.
- **Improve** (`actions.improve`) — `needsMap`: claims the map, resets bearing and pitch to north-up (leaving centre and zoom untouched), then opens an OpenStreetMap note at the live centre and rounded zoom in a new tab. It does not dismiss the pane.

### Panel rule

`dismissPanel()` closes the side pane only below the desktop breakpoint (`isDesktop` is false, i.e. `<992px`), matching the Offline draw rule. `random` opts in with `dismissPanel: true`, so the fitted country is unobstructed on a phone; `improve` does not dismiss the pane. Neither closes it on desktop. Feature show actions (a route, recording or region) claim the map without dismissing the pane; Routes Navigate claims with `navigate` excluded and closes the pane itself on every breakpoint.

Only camera ownership is arbitrated. The registry does not manage GPS subscriptions, so a recording can continue while route navigation runs.

### Root state attributes

`.ogis-root` mirrors the registry and the active pane for debugging and E2E assertions:

| Attribute    | Values                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| `data-modes` | Space-separated active mode ids in registration order; the attribute is absent when no mode is active. |
| `data-pane`  | `info`, `menu`, or `closed`.                                                                           |

These are stable assertions for feature specs; assert them rather than inferring camera ownership from chip labels alone.

### Adding an action or mode

- **One-shot camera move** — add a descriptor to [`src/actions.js`](../src/actions.js) with `needsMap: true` (and `dismissPanel: true` when the result needs an unobstructed view), then call `perform`. Do not fit, fly or orient directly from the call site.
- **Sustained camera owner** — register a mode with an `active` ref and a synchronous, idempotent `stop({ handoff })`. Stop per-frame or gesture work and release suppression on a hand-off; persist and tear down on a full stop.
- **Action that enters a mode** — call `claimMap({ except })` (or set `except` on a descriptor) so claiming the map does not stop the mode that is about to start; Routes navigation does this.
- **Feature-level camera command** — if a feature fits the map without a descriptor (route, recording or region Show), call `claimMap()` before the fit.
- **Precondition** — put it in `requires`; a `false` result must leave modes, the panel and the camera untouched.

## Map failure surface

The only map-level failure UI is the quiet `.ogis-map-status` card rendered by `App.vue` when `mapStatus` is `error`: a centred, localised message under `map.status.*` with a Retry button, marked `role="alert"` and `data-map-status="error"`. It is absent from the DOM on the healthy path, and it sits below the corner controls and side panels. Retry reloads the page; see [Map — map status and recovery](./4.map.md#map-status-and-recovery).

There is no global toast, snackbar or notice system. Feature failures are contained at their source — a feature's own panel, a modal, or a local surface such as the map card — so the app never replaces a working map with a full-screen error. The full containment model is in [State and resilience](./16.state-and-resilience.md#crash-containment).

## Screen wake lock — `useWakeLock`

[`useWakeLock`](../src/composables/useWakeLock.js) keeps the display awake while the app is open. `App.vue` calls it on mount ([`App.vue:64`](../src/App.vue#L64)); per-instance state is cached in a module-level `Map` keyed by `instanceId`, matching the other composables.

- **Acquired on interaction, not load.** The Wake Lock API requires user activation, so `init()` attaches a `click` listener and requests `navigator.wakeLock.request("screen")` on the first click — and again on every later click, so a browser-initiated release (power saving, brief loss of visibility) is recovered silently.
- **Re-acquired on visibility.** Once activated, a `visibilitychange` listener re-requests the lock whenever the page becomes visible again (tab switch, screen lock).
- **Graceful when unsupported.** Without `navigator.wakeLock`, `init()` logs through the `wake-lock` debug channel and returns; request failures (including a non-secure context) are logged and swallowed, leaving app behaviour unaffected.
- **Nothing stored or rendered.** The composable has no storage key and no UI; the lock simply follows the browser lifecycle.
