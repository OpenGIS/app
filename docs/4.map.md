# Map — `useMap`

`useMap` manages the MapLibre GL JS map lifecycle: creation, globe projection, view persistence, and cleanup.

---

## URL hash — map view sharing

The app reads and writes the map view to the URL hash in [OpenStreetMap format](https://wiki.openstreetmap.org/wiki/Browsing#Linking_to_a_specific_location), extended with camera tilt and bearing:

```
#map={zoom}/{lat}/{lng}/{pitch}/{bearing}
```

Example: `#map=12/51.507400/-0.127800/45/120`

Zoom is a whole number, latitude/longitude carry six decimal places, and pitch/bearing are whole degrees (bearing normalised 0–360). On read, a three-segment `#map={zoom}/{lat}/{lng}` hash is also accepted, with pitch and bearing defaulting to 0.

If the URL contains a `#map=…` hash on page load, it is used as the initial map view — taking priority over any previously persisted view. This lets you share a specific location by URL.

As the map is panned or zoomed, the URL hash is updated automatically (throttled to once per second). The hash and `localStorage` view stay in sync except while a controller owns the camera and suppresses persistence (see [View persistence](#view-persistence)).

[`formatUrlHash()`](../src/composables/useUrlHash.js) is the single source of truth for the format: `useMap` uses it for the live hash, and the Info panel uses it for its share URL (see [UI](./5.ui.md)).

## Globe projection

The map boots in the globe projection on every load: `useMap` calls `map.setProjection({ type: 'globe' })` on the `style.load` event. MapLibre automatically transitions between globe (low zoom) and mercator (high zoom) — zooming out from any location returns to the 3D globe view, capped at the full-globe view (`minZoom: 1`). The one exception is the offline region-selection drag, which scopes a mercator switch to the drawing itself and restores the previous projection when the draw stops (see [View orientation](#view-orientation)).

On a true cold start (no stored view, no URL hash), the map fits the country resolved by the cold-start cascade — see [Cold-start country focus](#cold-start-country-focus). Returning users are taken to their last-known location; zooming out from anywhere returns to the globe.

## View orientation

[`useOrientView.js`](../src/composables/useOrientView.js) exposes the orient facility: an `orientView()` entry point that resets the view to a flat, north-up camera — bearing 0, pitch 0, active projection untouched — with two targets:

- **Current camera** (default) — eases bearing and pitch to 0, skipping the ease when the view is already north-up and flat (within a small angular epsilon). Projection, centre and zoom are untouched.
- **Current location** (`orientView({ target: { lat, lng } })`) — flies to the location at a zoom fitted to the line-of-sight horizon disc for a 1.83 m eye height, computed from the live canvas size and target latitude. The duration blends a distance curve with a bearing-rotation floor, so long flights stay gentle.

`orientView()` returns `false` when there is nothing to act on — no map, or (location target) invalid coordinates or a canvas without a usable size — and `true` once the camera target is applied or the flight has started. Flights never set `essential` or `maxDuration`: MapLibre zeroes their duration for reduced-motion users, and no call site can turn the flight into an instant jump.

`useOrientView(explicitInstanceId?)` resolves the instance via `inject('ogisAppId')` when no id is passed. `useLocate` passes its own id, so the flight targets the same instance even though locate is installed outside component setup.

Projection switching is separate and scoped: `switchProjection(type = 'mercator')` records the currently active projection, applies the switch only when it differs, and returns an idempotent restore handle that reapplies the recorded value. Offline region selection is its only call site, so a mercator switch lasts exactly as long as the drag.

**Following** is the third-person chase view. [`useFollowCamera.js`](../src/composables/useFollowCamera.js) is the camera driver behind locate's `following` state: it takes the camera over (cancelling any in-flight animation), suppresses view persistence, then drives the map each animation frame towards a pose derived from the fix stream — damped centre, bearing, pitch and zoom. The pose is third-person from entry: pitch rests at 45° and tilts further along the fixed speed curve to 60° at 100 km/h, zoom rests at 17.5 and pulls back by 0.5 level to 17.0 at 100 km/h — both clamped to the map's configured ranges — and a look-ahead offset of up to 20 % of the viewport height seats the user in the lower third. The first target after the driver starts seeds an eased, ~1600 ms hand-off glide from the inherited wide, flat locate pose — pitch 0 at the horizon-fit zoom, some 5.85 zoom levels away — into that third-person pose, with each frame's zoom movement capped at 0.35 level so a slow renderer cannot jump-cut it; reduced-motion users snap instead. That wide flat view belongs to the first LOCATE click alone — the `active` state's one-shot orientation flight. Fixes arrive at ~1 Hz and are dead-reckoned forward between updates.

Any user-initiated camera movement suspends the driver — the camera stays where the user put it, while the locate chip still reads Following — and after 5 s without a camera-changing interaction it glides back to the follow pose over 1.2 s; reduced-motion users get an instant snap. The pure maths lives in [`src/utils/follow.js`](../src/utils/follow.js) and the tuning in `followCameraDefaults` in [`src/defaults/maplibre.js`](../src/defaults/maplibre.js).

Call sites:

- **Locate** — while `active`, the one-shot orientation flight on the first fix delegates to the facility; the one-shot flag and `map:ready` retry lifecycle stay in [`useLocate.js`](../src/composables/useLocate.js). Moving to `following` hands the camera to [`useFollowCamera.js`](../src/composables/useFollowCamera.js), which cancels any in-flight flight and glides from the inherited wide pose into the third-person chase pose. Both are projection-neutral, so locate keeps the globe. Locate markers re-sync on the map's `idle` and `moveend` events with a bounded retry until the map settles, so a far fix whose terrain DEM error aborts MapLibre's move dispatch still lands its marker. See [UI — corner controls](./5.ui.md#corner-controls).
- **Offline region selection** — entering region selection calls `switchProjection('mercator')` and resets the rotation, so the drag-drawn box is stamped on a flat map; the recorded previous projection is restored when the draw stops, and centre and zoom are untouched throughout. See [Offline — region selection](./12.offline.md#region-selection).

The pure helpers live in [`src/utils/orient.js`](../src/utils/orient.js) — `horizonDistanceMetres`, `fitZoomForDisc`, `shortestBearingDelta` and `orientFlightDurationMs` — tuned by `orientCameraDefaults` in [`src/defaults/maplibre.js`](../src/defaults/maplibre.js).

The projection is **not** persisted: the stored view covers centre, zoom, pitch and bearing only, so every load boots in globe and MapLibre's own globe↔mercator transition applies. Because every switch is scoped, the visit returns to the globe when the flow that needed mercator ends.

## `useMap` API

### Initialising the map

Called once from `App.vue` with a Vue template ref for the map container:

```js
import { ref } from "vue";
import { useMap } from "@/composables/useMap.js";

const mapContainer = ref(null);
useMap(mapContainer, {});
```

```html
<div ref="mapContainer" class="ogis-map" />
```

`useMap` registers `onMounted`/`onUnmounted` hooks. On mount, a `maplibregl.Map` is created with the defaults from [`src/defaults/maplibre.js`](../src/defaults/maplibre.js) — the OpenGIS outdoors style, initial `[0, 0]` centre at zoom 1 with `minZoom: 1`, and MapLibre's built-in attribution control disabled (`attributionControl: false`) in favour of the custom chip described in [UI](./5.ui.md). On unmount, the map is destroyed and an `emitter.emit('destroy')` is fired for feature cleanup.

### Accessing the map instance

From any composable or feature after setup:

```js
import { getMapInstance } from "@/composables/useMap.js";

const map = getMapInstance(instanceId);
if (map) map.addSource("my-source", { type: "geojson", data: { ... } });
```

`getMapInstance` returns the live map or `null` before load. Use it in geolocation callbacks and event handlers where a Vue inject context is unavailable.

### Map readiness signals

`useMap` publishes two `data-` attributes on the `.ogis-map` container, consumed by the E2E suite and useful when debugging load order:

| Attribute        | Published when                                                                           | Cleared                      |
| ---------------- | ---------------------------------------------------------------------------------------- | ---------------------------- |
| `data-map-ready` | `style.load` fires — the same point the instance is published and `map:ready` is emitted | never while mounted          |
| `data-map-idle`  | `!map.isMoving() && map.areTilesLoaded()` holds                                          | on `movestart` / `zoomstart` |

`data-map-idle` is predicate-driven rather than purely `idle`-event-driven. MapLibre's `idle` is the primary trigger, but it is not guaranteed — when the final render pass schedules no next frame (e.g. every tile of a source is absent), the tile manager can settle without firing it. `moveend`/`zoomend`/`sourcedata`/`load` therefore re-arm a bounded animation-frame retry (600 frames, ~10 s at 60 fps) that publishes the attribute once the predicate holds. See [Testing — Waiting for the map](./9.testing.md#waiting-for-the-map).

### View persistence

The map center, zoom, pitch and bearing are saved to `localStorage` under `ogis_view_{instanceId}` after every movement (throttled to 1 s). On reload the saved view is restored via `map.jumpTo()`; older stored views without pitch/bearing are read as 0.

The follow camera persists through the same path but not per frame. While the driver is active, [`setMapViewSuppressed(instanceId)`](../src/composables/useMap.js) suppresses controller-driven writes — its per-frame `jumpTo` moves write no hash, no `ogis_view_*` and no `view:change` — while user-originated moves (exploration) persist as usual. A full follow stop (or an error) releases suppression and [`persistMapView(instanceId)`](../src/composables/useMap.js) writes the live camera exactly once. A **hand-off** to a map action is different: `stop({ persist: false })` releases suppression without persisting, so the incoming action's camera move is the one that reaches storage and the hash (see [UI — hand-off semantics](./5.ui.md#hand-off-semantics)). Map teardown releases suppression without persisting. See [View orientation](#view-orientation).

Initial-view priority is: `?country=` override → URL hash → stored view → cold-start country focus. On a true cold start — or when `?country=` forces the focus — `mapView` stays `null` until the country fit completes; the fit's `moveend` persists the view, so the share URL appears once the map has been framed.

### Cold-start country focus

On load, the `style.load` handler resolves the initial focus from these sources, highest priority first:

1. **`?country=` query param** — forces the focus and outranks both the `#map=` hash and any stored view. `?country=XX` (a valid alpha-2 code, case-insensitive) fits that country; `?country=random` fits a random country on every load — the param survives `replaceState`, so a refresh makes a fresh draw. Empty or unknown values are ignored, so the normal rules apply.
2. **`#map=` URL hash** — an explicitly shared view (see [URL hash](#url-hash--map-view-sharing)).
3. **Stored view** — the last view persisted to `localStorage`.
4. **Cold-start cascade** — on a true cold start (neither of the above):
   1. `countryCodeFromTimeZone()` ([`src/utils/countries.js`](../src/utils/countries.js)) resolves the browser's IANA timezone to a region using a lazily built, cached reverse map of `Intl.Locale("und-<code>").getTimeZones()`. It is feature-checked (`getTimeZones` absent → `null`), and `UTC`/unknown zones resolve to `null`.
   2. The first raw browser language (`navigator.languages[0]` — not the resolved app locale or `?locale=`) is passed to `countryCodeFromLocale()`, which maximizes it with `Intl.Locale(...).maximize().region` — `en-GB` → `GB`, `fr` → `FR` — and returns `null` when no region is available.
   3. If neither resolves, a random country is chosen.

`countryCodeToBounds(code)` resolves the region against the frozen `COUNTRY_BOUNDS` table (bounding boxes migrated unmodified from Waymark-JS's `country_code_to_bounds`), preferring the `WRAP_OVERRIDES` table where present; an unknown or missing code falls back to a random country. `WRAP_OVERRIDES` holds the antimeridian-crossing countries (FJ, RU) with west > east — bounds derived once from Natural Earth 110m admin-0. MapLibre's `fitBounds` → `cameraForBounds` calls `adjustAntiMeridian()`, which unwraps them automatically, so no special call-site handling is needed.

The fit uses `map.fitBounds(bounds, { padding, duration: 0 })`, where `padding = Math.round(min(containerWidth, containerHeight) * 0.1)` — proportional to the smaller viewport axis, so framing stays consistent across phone and desktop. `duration: 0` completes synchronously. When the side panel is open on desktop, the map container itself is narrowed (`left`/`width` via `.ogis-map.panel-open`, [`src/assets/sass/theme.scss:312`](../src/assets/sass/theme.scss#L312)), so the fit centres the country in the visible map area.

Because the fit is a programmatic move, the `moveend` handler persists it to `localStorage` and the URL hash and emits `view:change` — the same path as any other camera move. No hash is written from the constructor defaults before the fit. Returning users and shared `#map=` links are unaffected unless a `?country=` override is present.

### Scale bar

A `ScaleControl` is added to the bottom-left corner. The unit (metric/imperial) follows the OS/browser region (inferred from the preferred language) and updates reactively.

### Multilingual map labels

On load, `useMap` applies a coalesce expression to every OSM name field across all symbol layers:

```
name:{locale}  →  name  →  name:en
```

The expression updates reactively when the OS/browser language changes — no page reload required.

See [Locale](./7.locale.md#osm-multilingual-names) for details.

### Returned API

```js
const { map, mapView } = useMap();
```

| Property  | Type                                            | Description                                                                                                                                                                                                                    |
| --------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `map`     | `maplibregl.Map \| null`                        | Active MapLibre instance, or `null` before load                                                                                                                                                                                |
| `mapView` | `Ref<{lat, lng, zoom, pitch, bearing} \| null>` | Reactive **persisted** view, updated through the same path as storage and the hash. It can lag the live camera while a controller suppresses persistence (for example, following); read the MapLibre camera for the live pose. |
