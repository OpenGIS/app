# Offline — region download

The Offline feature lets users download a map region (tiles + glyphs) so it works without a connection. It has no backend — it pre-warms the service worker's Cache API by fetching every resource, and keeps the existing free tile sources.

---

## Overview

Offline support is built on two cooperating pieces:

- **`public/sw.js`** — a hand-rolled service worker (no Workbox) that caches the app shell and cross-origin map resources as they are fetched.
- **`src/features/offline/`** — the download feature that pre-warms that cache for a chosen region.

There is no backend and no new tile provider. The feature simply enumerates the URLs the current map style would request for a region and fetches them all; the service worker caches successful GETs automatically, so the region is available offline. See [`src/features/offline/index.js`](../src/features/offline/index.js) and [`public/sw.js`](../public/sw.js).

---

## The service worker

`public/sw.js` maintains two caches:

| Cache | Name            | Contents                                                                                               |
| ----- | --------------- | ------------------------------------------------------------------------------------------------------ |
| Shell | `ogis-shell-v1` | App shell: `/`, `/index.html`, and same-origin hashed JS/CSS bundles                                   |
| Map   | `ogis-map-v1`   | Cross-origin map resources: style JSON, vector/raster tiles, DEM hillshades, glyphs, sprites, TileJSON |

The map cache is keyed by hostname — any path on these hosts is a candidate for offline caching ([`public/sw.js:14`](../public/sw.js#L14)):

```
tiles.openfreemap.org
tiles.mapterhorn.com
tile.ogis.app
raw.githubusercontent.com
```

### Registration and gating

Registration is controlled by [`src/utils/serviceWorker.js`](../src/utils/serviceWorker.js) (`setupServiceWorker()`), called at the end of [`src/main.js`](../src/main.js#L125). The worker itself ([`public/sw.js`](../public/sw.js)) is environment-agnostic; only the registration is gated:

| Context                                   | Behaviour                                                                                     |
| ----------------------------------------- | --------------------------------------------------------------------------------------------- |
| Production build (`import.meta.env.PROD`) | Registers `/sw.js`                                                                            |
| Dev with `VITE_SW=1`                      | Registers `/sw.js` — the opt-in used by E2E                                                   |
| Dev (default)                             | Does **not** register; unregisters any existing worker and deletes every cache for the origin |

The dev default is deliberate **self-healing**: registering the worker in Vite dev is harmful because the worker is cache-first for same-origin requests (see [Fetch strategy](#fetch-strategy)), so it used to cache Vite's dev module graph and `/@vite/client` — which hardcodes a per-server-instance HMR token. The stale token broke the WebSocket (`[vite] failed to connect to websocket`) and left a corrupted module graph. Now a normal dev visit removes the old registration and purges all origin caches, so a poisoned profile recovers on its next reload.

`setupServiceWorker()` returns `{ registered, cleanedRegistrations, cleanedCaches }` and logs cleanup problems through the `service-worker` debug channel. Its browser globals are injectable, so the behaviour is unit-tested in [`tests/unit/serviceWorker.test.js`](../tests/unit/serviceWorker.test.js).

The E2E webServer opts in with `VITE_SW: "1"` ([`playwright.config.js:147`](../playwright.config.js#L147)) so the browser suite exercises the SW paths; [`tests/e2e/sw.spec.js`](../tests/e2e/sw.spec.js) asserts the worker registers on load and that a reload boots cleanly while it is in control.

### Fetch strategy

The fetch handler ([`public/sw.js:75`](../public/sw.js#L75)) branches by request type:

- **Navigation** (`request.mode === 'navigate'`) — **network-first**, falling back to the cached `index.html` offline. A successful response also refreshes the cached shell so hashed asset references stay in sync after a deploy.
- **Cross-origin map resources** — **cache-first** with a network fallback. Only successful GET responses are stored; opaque or error responses are skipped. This is what makes the pre-warm work: the download just fetches each URL and the SW stores it.
- **Same-origin assets** — **cache-first** with a network fallback, populating the shell cache on first fetch.

### Region purge

The SW listens for a `message` event ([`public/sw.js:52`](../public/sw.js#L52)). When it receives `{ type: 'DELETE_URLS', urls }` it deletes each URL from the map cache and replies on the sender's `MessageChannel` port with `{ type: 'DELETE_URLS_DONE', deleted }` — the count of URLs actually removed. This is how deleting a region frees its tiles.

## The download flow

The feature lives in `src/features/offline/`:

```
src/features/offline/
  index.js            ← feature object + API + SW purge wiring
  tiles.js            ← pure tile-math (unit-testable, no DOM/map deps)
  download.js         ← estimate + download manager
  OfflinePanel.vue    ← side panel
```

### Region selection

The panel lets the user drag a box on the map to select a region ([`OfflinePanel.vue:69`](../src/features/offline/OfflinePanel.vue#L69)). While drawing, MapLibre's `dragPan`, `boxZoom`, `doubleClickZoom`, `touchZoomRotate` and `touchPitch` are disabled so the drag is captured by the panel; a `mousedown`/`mousemove`/`mouseup` or `touchstart`/`touchmove`/`touchend` sequence produces a `{ west, south, east, north }` bounds object (`touchcancel` cleans up an interrupted gesture). A click without an actual drag (movement < 4px) is ignored. On mobile/tablet the panel closes when drawing starts so the map is fully visible, and reopens automatically after a successful draw; on desktop the panel stays open. Min/max zoom inputs are clamped to `0..22`.

### Per-source tile enumeration

`estimateRegion` ([`download.js:41`](../src/features/offline/download.js#L41)) and `buildRegionUrls` ([`download.js:171`](../src/features/offline/download.js#L171)) iterate every source in the current style. For each source the chosen zoom range is clamped to the source's own `minzoom`/`maxzoom`, then `enumerateTiles` ([`tiles.js:82`](../src/features/offline/tiles.js#L82)) generates every `{ z, x, y }` tile in the bounds across that range. `tileUrlTemplateToUrl` ([`tiles.js:108`](../src/features/offline/tiles.js#L108)) substitutes `{z}`, `{x}`, `{y}` and `{-y}` into the source's URL template.

### Live TileJSON resolution

Sources with a `tiles` array use the first template directly. Sources with a `url` (TileJSON) — such as the `openmaptiles` planet source whose path contains a **dated slug** that changes on each rebuild — are fetched and their `tiles[0]` template used ([`tiles.js:128`](../src/features/offline/tiles.js#L128)). This means a download always targets the **current** planet build. The TileJSON's own `minzoom`/`maxzoom` are preferred when the source doesn't specify them.

### Glyph pre-fetch

Labels need glyphs, so the download also pre-fetches every glyph range for every distinct `text-font` fontstack in the style. `collectFontstacks` ([`download.js:65`](../src/features/offline/download.js#L65)) dedupes fontstacks from symbol layers, and `glyphUrlsForTemplate` ([`download.js:87`](../src/features/offline/download.js#L87)) expands each into the 256-range glyph URLs (`0`, `256`, … `65280`) using the style's `glyphs` template.

### Pre-warm via fetch

`downloadRegion` ([`download.js:246`](../src/features/offline/download.js#L246)) builds the full URL list (tiles + glyphs) and passes it to `fetchAll` ([`download.js:115`](../src/features/offline/download.js#L115)). `fetchAll` fetches with **8-way concurrency**, drains each response body (so it can be cached fully and connections reused), and reports progress as each URL resolves. It accepts an `AbortSignal` for cancellation; per-URL failures are ignored rather than aborting the whole download, but an abort propagates as an `AbortError`.

> [!NOTE]
> The download never touches the Cache API directly. It relies on the service worker's fetch handler to store each successful GET in the map cache — the SW is the single writer.

## Feature API

`OfflineFeature.install` provides `offline` via `app.provide` ([`index.js:170`](../src/features/offline/index.js#L170)):

| Member                                                       | Type           | Purpose                                                                                                                    |
| ------------------------------------------------------------ | -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `regions`                                                    | reactive array | Downloaded region metadata, persisted to `ogis_offline-regions_{instanceId}`                                               |
| `estimate(bounds, minZoom, maxZoom)`                         | async          | Returns `{ tileCount, estimatedBytes }`                                                                                    |
| `download({ bounds, minZoom, maxZoom, onProgress, signal })` | async          | Downloads the region; returns `{ tileCount, glyphCount, totalCount }`                                                      |
| `addRegion(meta)`                                            | fn             | Appends region metadata (`id`, `createdAt`, bounds, zoom, counts)                                                          |
| `deleteRegion(region)`                                       | async          | Removes metadata and best-effort purges its tiles from the SW map cache                                                    |
| `showRegion(region)`                                         | fn             | Draws the region's bounds as a green polygon and fits the map to it                                                        |
| `getStorageInfo()`                                           | async          | Returns `{ usage, quota, persisted }` from the Storage API                                                                 |
| `requestPersistence()`                                       | async          | Requests persistent storage via `navigator.storage.persist()` (falls back to `persisted()`); returns the resulting boolean |
| `getMap()`                                                   | fn             | Returns the MapLibre map instance or `null`                                                                                |

Region metadata is stored via `useStorage('offline-regions', [])` — the localStorage key `ogis_offline-regions_{instanceId}` ([`index.js:15`](../src/features/offline/index.js#L15)).

### Panel UX

`OfflinePanel.vue` ([`OfflinePanel.vue`](../src/features/offline/OfflinePanel.vue)) provides:

- **Select region** — drag-to-draw box on the map, with a live overlay rectangle. On mobile/tablet the panel closes while drawing and reopens after a successful draw.
- **Min/max zoom** — number inputs clamped to `0..22`.
- **Estimate size** — shows tile count and estimated bytes; warns when the region is large (>200MB) or when it plus current usage may exceed the storage quota.
- **Download region** — progress bar with `done / total` and percentage, plus a **Cancel** button that aborts the in-flight download.
- **Storage** — `X of Y used` with a usage bar and a persistent/clearable indicator.
- **Downloaded Regions** — list with name, zoom range, tile count, size and date, each with a **Delete** button.

The Offline Maps tab in the side panel opens `OfflinePanel.vue`.

## Storage

The Cache API shares the origin's storage quota with everything else. The panel reads usage via `navigator.storage.estimate()` and persistence via `navigator.storage.persisted()` ([`index.js:134`](../src/features/offline/index.js#L134)). When the Storage API is unavailable it returns zeros/`false`.

On the first download the panel also requests persistent storage. `requestPersistence()` ([`index.js:156`](../src/features/offline/index.js#L156)) calls `navigator.storage.persist()`, falling back to `navigator.storage.persisted()` when `persist` is unavailable, and returns the resulting boolean. The panel fires it right after the user confirms a download — non-blocking, in parallel with the download — and awaits it before refreshing the storage badge ([`OfflinePanel.vue:229`](../src/features/offline/OfflinePanel.vue#L229)), so the **Persistent** / **May be cleared** badge reflects the granted state.

Persistence reduces the risk of the browser evicting downloaded tiles under disk pressure, but it is **not guaranteed** — it is browser-dependent. Chrome grants it for installed PWAs or after user engagement; iOS Safari doesn't implement the API but auto-grants persistence to home-screen PWAs.

Deleting a region frees its tiles: `deleteRegion` removes the metadata first (so the list updates immediately), then re-enumerates the region's URLs and posts them to the service worker for a `DELETE_URLS` purge ([`index.js:75`](../src/features/offline/index.js#L75)). The purge is best-effort and bounded (3s timeout); if there is no SW controller or the URLs can't be resolved, it simply skips the purge.

## Known limitations

- **Volatile TileJSON slug.** The `openmaptiles` planet source's path contains a dated slug that changes on rebuild. A download always targets the current build, but if the slug changes between download and offline use (or between download and delete), some cached URLs may no longer match — deletion is best-effort and may leave orphaned tiles.
- **Best-effort delete.** If the style/source can't be resolved at delete time, or there's no active service worker, the region's tiles are not purged (only the metadata is removed).
- **Origin quota.** Offline tiles count against the browser's per-origin storage quota. Very large regions may not fit; the panel warns when an estimate plus current usage exceeds the quota.
- **Requires an initial connection** to download a region (and to load the app shell the first time).
- **Cache versioning.** Cache names are versioned (`-v1`); bumping them invalidates the old cache on the next `activate`.
