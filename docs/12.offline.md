# Offline — region download

The Offline feature lets users download a map region (tiles + glyphs) so it works without a connection. It has no backend — it pre-warms the service worker's Cache API by fetching every resource, and keeps the existing free tile sources.

---

## Overview

Offline support is built on two cooperating pieces:

- **`public/sw.js`** — a hand-rolled service worker (no Workbox) that caches the app shell and cross-origin map resources as they are fetched.
- **`src/features/offline/`** — the download feature that pre-warms that cache for a chosen region.

There is no backend and no new tile provider. The feature simply enumerates the URLs the current map style would request for a region and fetches them all; the service worker caches successful GETs automatically, so the region is available offline. See [`src/features/offline/index.js`](../src/features/offline/index.js) and [`public/sw.js`](../public/sw.js).

---

## The service worker

`public/sw.js` maintains two caches:

| Cache | Name            | Contents                                                                                               |
| ----- | --------------- | ------------------------------------------------------------------------------------------------------ |
| Shell | `ogis-shell-v1` | App shell: `/`, `/index.html`, and same-origin hashed JS/CSS bundles                                   |
| Map   | `ogis-map-v1`   | Cross-origin map resources: style JSON, vector/raster tiles, DEM hillshades, glyphs, sprites, TileJSON |

The map cache is keyed by hostname — any path on these hosts is a candidate for offline caching ([`public/sw.js:14`](../public/sw.js#L14)):

```
tiles.openfreemap.org
tiles.mapterhorn.com
tile.ogis.app
raw.githubusercontent.com
```

### Registration and gating

Registration is controlled by [`src/utils/serviceWorker.js`](../src/utils/serviceWorker.js) (`setupServiceWorker()`), called at the end of [`src/main.js`](../src/main.js#L204). The worker itself ([`public/sw.js`](../public/sw.js)) is environment-agnostic; only the registration is gated:

| Context                                   | Behaviour                                                                                     |
| ----------------------------------------- | --------------------------------------------------------------------------------------------- |
| Production build (`import.meta.env.PROD`) | Registers `/sw.js`                                                                            |
| Dev with `VITE_SW=1`                      | Registers `/sw.js` — the opt-in used by E2E                                                   |
| Dev (default)                             | Does **not** register; unregisters any existing worker and deletes every cache for the origin |

The dev default is deliberate **self-healing**: registering the worker in Vite dev is harmful because the worker is cache-first for same-origin requests (see [Fetch strategy](#fetch-strategy)), so it used to cache Vite's dev module graph and `/@vite/client` — which hardcodes a per-server-instance HMR token. The stale token broke the WebSocket (`[vite] failed to connect to websocket`) and left a corrupted module graph. Now a normal dev visit removes the old registration and purges all origin caches, so a poisoned profile recovers on its next reload.

`setupServiceWorker()` returns `{ registered, cleanedRegistrations, cleanedCaches }`. A registration failure is reported through `reportError` with `{ source: "service-worker", phase: "register" }` and still resolves with `registered: false`; dev cleanup problems log through the `service-worker` debug channel. Its browser globals and reporter are injectable, so the behaviour is unit-tested in [`tests/unit/serviceWorker.test.js`](../tests/unit/serviceWorker.test.js).

The E2E webServer opts in with `VITE_SW: "1"` ([`playwright.config.js:174`](../playwright.config.js#L174)) so the browser suite exercises the SW paths; [`tests/e2e/sw.spec.js`](../tests/e2e/sw.spec.js) asserts the worker registers on load and that a reload boots cleanly while it is in control.

### Fetch strategy

The fetch handler ([`public/sw.js:89`](../public/sw.js#L89)) branches by request type:

- **Navigation** (`request.mode === 'navigate'`) — **network-first**, falling back to the cached `index.html` offline. A successful response also refreshes the cached shell so hashed asset references stay in sync after a deploy.
- **Cross-origin map resources** — **cache-first** with a network fallback. Only successful GET responses are stored; opaque or error responses are skipped. This is what makes the pre-warm work: the download just fetches each URL and the SW stores it.
- **Same-origin assets** — **cache-first** with a network fallback, populating the shell cache on first fetch.

Every cache write follows the same path: `cacheResponse` clones the response, passes the `cache.put` promise to `event.waitUntil(...)` so the write is not cancelled when the worker goes idle, and swallows a rejection so a failed cache write cannot break the response returned to the page. This applies to navigation shell refreshes, cross-origin map resources and same-origin assets alike.

### Region purge

The SW listens for a `message` event ([`public/sw.js:66`](../public/sw.js#L66)). When it receives `{ type: 'DELETE_URLS', urls }` it deletes each URL from the map cache and replies on the sender's `MessageChannel` port with `{ type: 'DELETE_URLS_DONE', deleted }` — the count of URLs actually removed. This is how deleting a region frees its tiles.

## The download flow

The feature lives in `src/features/offline/`:

```
src/features/offline/
  index.js            ← feature object + API + SW purge wiring
  tiles.js            ← pure tile-math (unit-testable, no DOM/map deps)
  download.js         ← estimate + download manager
  OfflinePanel.vue    ← side panel
```

### Region selection

The panel lets the user drag a box on the map to select a region ([`OfflinePanel.vue:77`](../src/features/offline/OfflinePanel.vue#L77)). Entering selection claims the map from any active mode — following and route navigation hand the camera over — then resets the camera rotation to a flat, north-up view and switches the map to the mercator projection for the duration of the drag — the scoped [`switchProjection('mercator')` facility](./4.map.md#view-orientation) records the previous projection, and `orientView()` zeroes bearing and pitch; centre and zoom are untouched throughout. The previous projection is restored when the drawing stops (drag end, click-skip, touch-cancel, toggle-off or unmount), so a visit that booted in globe returns to it. While drawing, MapLibre's `dragPan`, `boxZoom`, `doubleClickZoom`, `touchZoomRotate` and `touchPitch` are disabled so the drag is captured by the panel; a `mousedown`/`mousemove`/`mouseup` or `touchstart`/`touchmove`/`touchend` sequence produces a `{ west, south, east, north }` bounds object (`touchcancel` cleans up an interrupted gesture). A click without an actual drag (movement < 4px) is ignored. Starting a draw registers the `draw` mode ([see UI actions and map modes](./5.ui.md#ui-actions-and-map-modes)). On mobile/tablet the panel closes when drawing starts so the map is fully visible, and reopens automatically after a successful draw; on desktop the panel stays open. A hand-off stop — another map action claims the camera while drawing — ends the draw without reopening the panel; only a normally completed draw reopens it. Min/max zoom inputs are clamped to `0..22`.

### Per-source tile enumeration

`estimateRegion` ([`download.js:45`](../src/features/offline/download.js#L45)) and `buildRegionUrls` ([`download.js:200`](../src/features/offline/download.js#L200)) iterate every source in the current style. For each source the chosen zoom range is clamped to the source's own `minzoom`/`maxzoom`, then `enumerateTiles` ([`tiles.js:82`](../src/features/offline/tiles.js#L82)) generates every `{ z, x, y }` tile in the bounds across that range. `tileUrlTemplateToUrl` ([`tiles.js:108`](../src/features/offline/tiles.js#L108)) substitutes `{z}`, `{x}`, `{y}` and `{-y}` into the source's URL template.

### Live TileJSON resolution

Sources with a `tiles` array use the first template directly. Sources with a `url` (TileJSON) — such as the `openmaptiles` planet source whose path contains a **dated slug** that changes on each rebuild — are fetched and their `tiles[0]` template used ([`tiles.js:128`](../src/features/offline/tiles.js#L128)). This means a download always targets the **current** planet build. The TileJSON's own `minzoom`/`maxzoom` are preferred when the source doesn't specify them.

### Glyph pre-fetch

Labels need glyphs, so the download also pre-fetches every glyph range for every distinct `text-font` fontstack in the style. `collectFontstacks` ([`download.js:69`](../src/features/offline/download.js#L69)) dedupes fontstacks from symbol layers, and `glyphUrlsForTemplate` ([`download.js:91`](../src/features/offline/download.js#L91)) expands each into the 256-range glyph URLs (`0`, `256`, … `65280`) using the style's `glyphs` template.

### Pre-warm via fetch

`downloadRegion` ([`download.js:286`](../src/features/offline/download.js#L286)) builds the full URL list (tiles + glyphs) and passes it to `fetchAll` ([`download.js:122`](../src/features/offline/download.js#L122)). `fetchAll` fetches with **8-way concurrency** and reports progress as each URL settles.

Each request is bounded by a **15 s timeout** (`FETCH_TIMEOUT_MS`, [`download.js:27`](../src/features/offline/download.js#L27)): a stalled connection is aborted and counted as a failure. A URL counts as successful only after `response.ok` **and** a completed `arrayBuffer()` drain — a non-ok status, network error, body-read error or timeout fails that URL while the remaining requests continue. The caller's `AbortSignal` is forwarded to every in-flight request, so a caller abort still aborts the whole download and propagates as an `AbortError`.

`downloadRegion` returns **actual** outcomes rather than planned counts:

| Field            | Meaning                                             |
| ---------------- | --------------------------------------------------- |
| `tileCount`      | Tile URLs fetched successfully                      |
| `glyphCount`     | Glyph URLs fetched successfully                     |
| `totalCount`     | `tileCount + glyphCount`                            |
| `requestedCount` | Every URL planned for the region (tiles + glyphs)   |
| `failedCount`    | URLs that failed (non-ok, body, network or timeout) |

If no map tile succeeded — no tiles were planned, every tile failed, or only glyphs downloaded — `downloadRegion` throws `{ code: "download-empty" }`. The panel maps that to `panel.offline.empty` and saves no region, so an empty download never appears in the list.

> [!NOTE]
> The download never touches the Cache API directly. It relies on the service worker's fetch handler to store each successful GET in the map cache — the SW is the single writer.

## Feature API

`OfflineFeature.install` provides `offline` via `app.provide` ([`index.js:229`](../src/features/offline/index.js#L229)):

| Member                                                         | Type           | Purpose                                                                                                                                 |
| -------------------------------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `regions`                                                      | reactive array | Downloaded region metadata, persisted to `ogis_offline-regions_{instanceId}` in a versioned envelope                                    |
| `estimate(bounds, minZoom, maxZoom)`                           | async          | Returns `{ tileCount, estimatedBytes }`                                                                                                 |
| `download({ bounds, minZoom, maxZoom, onProgress, signal })`   | async          | Downloads the region; returns `{ tileCount, glyphCount, totalCount, requestedCount, failedCount }`                                      |
| [`addRegion(meta)`](../src/features/offline/index.js#L66)      | fn             | Appends region metadata (`id`, `createdAt`, bounds, zoom, actual tile count, failed/requested counts)                                   |
| [`deleteRegion(region)`](../src/features/offline/index.js#L99) | async          | Removes metadata, clears the overlay when that region is shown, and best-effort purges its tiles from the SW map cache                  |
| [`showRegion(region)`](../src/features/offline/index.js#L174)  | fn             | Claims the map from any active mode, draws the region's bounds as a green polygon, tracks it as the shown region and fits the map to it |
| `getStorageInfo()`                                             | async          | Returns `{ usage, quota, persisted }` from the Storage API                                                                              |
| `requestPersistence()`                                         | async          | Requests persistent storage via `navigator.storage.persist()` (falls back to `persisted()`); returns the resulting boolean              |
| `getMap()`                                                     | fn             | Returns the MapLibre map instance or `null`                                                                                             |

Region metadata is stored through the feature context under `ogis_offline-regions_{instanceId}` ([`index.js:27`](../src/features/offline/index.js#L27)):

```js
const regions = useStorage("offline-regions", {
  version: 1,
  defaults: [],
  hydrate: hydrateOfflineRegions,
  crossTab: true,
  onSync: () => reconcileRegions(),
}).state;
```

Values are written as a versioned envelope. `hydrateOfflineRegions` keeps the latest schema valid for panel formatting: malformed entries are dropped, and ids, names, bounds, zoom ranges, tile counts, byte estimates and `createdAt` must all be usable. When two entries share an id, the first is kept and later duplicates are dropped ([`hydrateOfflineRegions`](../src/resilience/hydrators/offlineRegions.js#L30)). A non-array top level falls back to an empty list and is quarantined. See [State and resilience — Hydration and validation](./16.state-and-resilience.md#hydration-and-validation).

### Panel UX

`OfflinePanel.vue` ([`OfflinePanel.vue`](../src/features/offline/OfflinePanel.vue)) provides:

- **Select region** — drag-to-draw box on the map, with a live overlay rectangle. On mobile/tablet the panel closes while drawing and reopens after a successful draw.
- **Min/max zoom** — number inputs clamped to `0..22`.
- **Estimate size** — shows tile count and estimated bytes; warns when the region is large (>200MB) or when it plus current usage may exceed the storage quota.
- **Download region** — progress bar with `done / total` and percentage, plus a **Cancel** button that aborts the whole in-flight download.
- **Partial download warning** — when some requests fail but at least one map tile succeeded, the region is saved with its actual tile count and a `panel.offline.partial` warning reports how many files succeeded out of those requested.
- **Storage** — `X of Y used` with a usage bar and a persistent/clearable indicator.
- **Downloaded Regions** — list with name, zoom range, actual tile count, estimated size and date, each with **Show** and **Delete** buttons. Showing a region draws its bounds as an `offline-region` GeoJSON overlay; deleting that same region removes the overlay.

All panel copy resolves through `t()` (`menu.offline` for the tab and heading, `panel.offline.*` for the rest), with sizes formatted for the active locale — see [Locale](./7.locale.md). Download failures surface through sentinel codes mapped to translated messages: `map-not-ready` → `panel.offline.errorMapNotReady`, `download-empty` → `panel.offline.empty`, and a caller abort → `panel.offline.cancelled`. A partial result shows `panel.offline.partial`; unknown download and delete failures fall back to the generic `panel.offline.failed` / `panel.offline.deleteFailed` messages, never the raw error text. The list's empty state uses `panel.offline.noRegions`.

The Offline Maps tab in the side panel opens `OfflinePanel.vue`.

## Storage

The Cache API shares the origin's storage quota with everything else. The panel reads usage via `navigator.storage.estimate()` and persistence via `navigator.storage.persisted()` ([`index.js:193`](../src/features/offline/index.js#L193)). When the Storage API is unavailable it returns zeros/`false`.

Region metadata is small next to the cached tiles, but it is still localStorage state: a write failure is silent, and the in-memory list survives for the session. The metadata store syncs live between tabs. When another tab adds, updates or removes a region, the receiving tab replaces its list and [`reconcileRegions()`](../src/features/offline/index.js#L157) reconciles the overlay: a shown region that disappeared loses the `offline-region` feature and its tracking id, while a shown region that still exists is redrawn without claiming the map or refitting the camera. Shared content is last-writer-wins; the list is replaced wholesale, not merged. See [State and resilience — Store inventory](./16.state-and-resilience.md#store-inventory).

On the first download the panel also requests persistent storage. `requestPersistence()` ([`index.js:215`](../src/features/offline/index.js#L215)) calls `navigator.storage.persist()`, falling back to `navigator.storage.persisted()` when `persist` is unavailable, and returns the resulting boolean. The panel fires it right after the user confirms a download — non-blocking, in parallel with the download — and awaits it before refreshing the storage badge ([`OfflinePanel.vue:309`](../src/features/offline/OfflinePanel.vue#L309)), so the **Persistent** / **May be cleared** badge reflects the granted state.

Persistence reduces the risk of the browser evicting downloaded tiles under disk pressure, but it is **not guaranteed** — it is browser-dependent. Chrome grants it for installed PWAs or after user engagement; iOS Safari doesn't implement the API but auto-grants persistence to home-screen PWAs.

Deleting a region frees its tiles: `deleteRegion` removes the metadata first (so the list updates immediately), clears the `offline-region` GeoJSON overlay when the deleted region is the one currently shown (`shownRegionId`, [`index.js:105`](../src/features/offline/index.js#L105)), then re-enumerates the region's URLs and posts them to the service worker for a `DELETE_URLS` purge ([`index.js:76`](../src/features/offline/index.js#L76)). The purge is best-effort and bounded (3s timeout); if there is no SW controller or the URLs can't be resolved, it simply skips the purge. The shown overlay is in-memory only: it is not restored after a reload.

## Known limitations

- **Volatile TileJSON slug.** The `openmaptiles` planet source's path contains a dated slug that changes on rebuild. A download always targets the current build, but if the slug changes between download and offline use (or between download and delete), some cached URLs may no longer match — deletion is best-effort and may leave orphaned tiles.
- **Best-effort delete.** If the style/source can't be resolved at delete time, or there's no active service worker, the region's tiles are not purged (only the metadata is removed).
- **Origin quota.** Offline tiles count against the browser's per-origin storage quota. Very large regions may not fit; the panel warns when an estimate plus current usage exceeds the quota.
- **Partial downloads are kept.** Once at least one map tile succeeds, the region is saved with whatever tiles and glyphs downloaded; the panel reports the failure counts but there is no automatic retry.
- **Tile-only size estimate.** The panel's estimate counts tile URLs only; the download also pre-fetches every glyph range, so the estimate understates both the bytes transferred and the progress total, which includes glyphs.
- **Per-request timeout.** Each request is bounded by 15 s, so a slow but healthy connection can fail individual requests. Those failures are counted and surfaced rather than hanging the download.
- **Requires an initial connection** to download a region (and to load the app shell the first time).
- **Cache versioning.** Cache names are versioned (`-v1`); bumping them invalidates the old cache on the next `activate`.
