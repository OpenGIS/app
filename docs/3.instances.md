# Instances

How ogis.app handles instance isolation and localStorage scoping.

---

## One Instance Per Page

The normal deployment is a single Vue app mounted to `#app`. There is one instance per JS context — one browser tab, one iframe.

The `instanceId` (injected as `ogisAppId`) defaults to `'app'` and is only overridden via the `?id=` URL parameter for iframe embedding.

---

## localStorage Key Format

All persisted state follows this key format:

```
ogis_{namespace}_{instanceId}
```

| Key                        | Namespace         | Version | Purpose                                                | Cross-tab |
| -------------------------- | ----------------- | ------- | ------------------------------------------------------ | --------- |
| `ogis_view_app`            | `view`            | 1       | Map centre, zoom, pitch and bearing                    | Yes       |
| `ogis_recordings_app`      | `recordings`      | 1       | Saved recordings and the interrupted active track      | No        |
| `ogis_routes_app`          | `routes`          | 1       | Imported route and waypoint documents                  | No        |
| `ogis_offline-regions_app` | `offline-regions` | 1       | Downloaded offline region metadata                     | No        |
| `ogis_locate_app`          | `locate`          | 2       | Permission flag, restorable mode and last accepted fix | No        |
| `ogis_navigation_app`      | `navigation`      | 1       | Route visibility and navigation ownership              | No        |
| `ogis_sync_app`            | `sync`            | 1       | Dormant backend sync queue                             | No        |

The `routes` and `recordings` namespaces hold versioned `v: 2` track documents; their shape and migration are described in [Tracks](./15.tracks.md). The `navigation` and `locate` schemas are covered in [State and resilience](./16.state-and-resilience.md).

Each value is written as a versioned envelope:

```json
{ "__ogisState": 1, "version": 1, "data": { "mapView": {} } }
```

A bare legacy value is read as version 0. An invalid value falls back to defaults and its raw contents are kept at `ogis_quarantine_{namespace}_{instanceId}` for debugging. The `instanceId` is always last, so both store keys and quarantine keys are easy to identify in browser DevTools.

The `view` store is the only cross-tab store: a camera move in one tab updates another tab without an echo write. Locate and navigation do not enable cross-tab sync on purpose. The full persisted-state contract — hydration, debounce, flush, reset, quota handling and session storage — is in [State and resilience](./16.state-and-resilience.md#persisted-state).

## `usePersistedState(namespace, definition, instanceId?)`

[`usePersistedState`](../src/resilience/persistedState.js) creates a reactive store that reads and writes through the versioned envelope:

```js
import { usePersistedState } from "@/resilience/persistedState.js";

const { state, flush, reset } = usePersistedState("my-feature", {
  version: 1,
  defaults: { enabled: false },
  hydrate: hydrateMyFeature,
});
```

The definition carries `version`, `defaults`, an optional `hydrate` and any of `storage`, `crossTab`, `debounce` and `onSync`. `state` is reactive, `flush()` writes immediately and `reset()` removes the key and restores defaults. Details and the full definition table are in [State and resilience — Persisted state](./16.state-and-resilience.md#persisted-state).

When called outside a component (e.g. in `src/main.js`), pass the `instanceId` explicitly:

```js
const store = usePersistedState(
  "recordings",
  { version: 1, defaults: { saved: [], active: null } },
  instanceId,
);
```

Features receive the same facility through `featureCtx.useStorage(namespace, definition)` and read `.state`; there is no separate `useStorage` composable. See [Features — Persistence and restore](./10.features.md#persistence-and-restore).

`resetInstanceState(instanceId)` removes every `ogis_*_{instanceId}` localStorage key for one instance, including quarantine copies, and leaves other instances untouched. The boot fallback's **Reset app data** action applies the same localStorage cleanup without importing the app, and additionally unregisters service workers and deletes `ogis-*` caches.

## iframe Isolation

When the app is embedded in an `<iframe>`, each iframe is a separate JS context with its own module instances. The `?id=` URL parameter ensures their `localStorage` keys are distinct:

```
iframe A (?id=map-a): ogis_view_map-a
iframe B (?id=map-b): ogis_view_map-b
```

Without different IDs the two iframes would overwrite each other's saved view.
