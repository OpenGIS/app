# Instances

How the On Route App handles instance isolation and localStorage scoping.

---

## One Instance Per Page

The normal deployment is a single Vue app mounted to `#app`. There is one instance per JS context — one browser tab, one iframe.

The `instanceId` (injected as `onrteAppId`) defaults to `'app'` and is only overridden via the `?id=` URL parameter for iframe embedding.

---

## localStorage Key Format

All persisted state follows this key format:

```
onrte_{namespace}_{instanceId}
```

| Key                    | Namespace    | Purpose                          |
| ---------------------- | ------------ | -------------------------------- |
| `onrte_view_app`       | `view`       | Map center, zoom, pitch, bearing |
| `onrte_recordings_app` | `recordings` | Saved and active recordings      |

The `instanceId` is always last, making keys easy to identify in browser DevTools.

---

## `useStorage(namespace, defaults)`

The `useStorage` composable creates a reactive object that reads from and writes to `localStorage` automatically.

```js
import { useStorage } from "@/composables/useStorage.js";

const prefs = useStorage("prefs", { zoom: 10 });
prefs.zoom = 12; // persists immediately
```

When called outside a component (e.g. in `src/main.js`), pass the `instanceId` explicitly:

```js
const stored = useStorage(
  "recordings",
  { saved: [], active: null },
  instanceId,
);
```

---

## iframe Isolation

When the app is embedded in an `<iframe>`, each iframe is a separate JS context with its own module instances. The `?id=` URL parameter ensures their `localStorage` keys are distinct:

```
iframe A (?id=map-a): onrte_view_map-a
iframe B (?id=map-b): onrte_view_map-b
```

Without different IDs the two iframes would overwrite each other's saved view.
