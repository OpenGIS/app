# Terminology

> Shared project language for ogis.app. Definitions here must be accurate and
> verifiable against the code and the workflows — they are used across docs,
> tests and commits.

## Demo area

The single, configurable geographic area for which the E2E suite vendors map
assets. The geometry is the opening ~2 km ("Day 13") slice of the committed GPS
fixture
[`tests/fixtures/recording.geojson`](../tests/fixtures/recording.geojson),
which starts at Grand Falls-Windsor, Newfoundland. It is defined once in
[`tests/fixtures/demo.mjs`](../tests/fixtures/demo.mjs) (exports
`DEMO`), which
[`tests/fixtures/map/demoArea.mjs`](../tests/fixtures/map/demoArea.mjs)
re-exports as `DEMO_AREA` and extends with area policy. The fixture pipeline
reads `DEMO_AREA` for:

| Config             | Value                                                                            | Meaning                                         |
| ------------------ | -------------------------------------------------------------------------------- | ----------------------------------------------- |
| `center`           | derived from the fixture slice                                                   | Canonical demo centre                           |
| `bounds`           | derived from the fixture slice (expanded to the target extents)                  | Box the fixture set covers                      |
| `screenshotZoom`   | `16`                                                                             | Zoom for the committed screenshot matrix        |
| `coverageZooms`    | every integer `0`–`16`                                                           | Zooms the fixture set covers                    |
| `excludedSources`  | `attribution`, `esri-satellite`                                                  | Sources deliberately not vendored, with reasons |
| `committableHosts` | `tiles.openfreemap.org`, `tiles.mapterhorn.com`, `tile.ogis.app`, `www.ogis.org` | Hosts whose assets may be committed             |
| `glyphRanges`      | `0-255`                                                                          | Committed glyph range per font stack            |
| `spriteScale`      | `1`                                                                              | Only the 1× sprite atlas is vendored            |

Consumers: the fixture generator (`refresh.mjs`), the tile enumeration
(`enumerate.mjs`), the UI-states screenshot spec (`ui-states.spec.js`) and the
demo-area unit test. The README hero spec (`readme.spec.js`) deliberately does
not use the fixture set — its heroes are live random-country captures.

Changing the demo area means editing `demo.mjs` (geometry) or `demoArea.mjs`
(policy), regenerating the fixtures (`npm run fixtures:refresh`) and
regenerating the committed screenshots.

## Fixture set

The committed, generated map assets that the E2E suite serves same-origin, so
every spec except the deliberately live README hero captures makes **zero live
external requests**:

- [`style.json`](../tests/fixtures/map/style.json) — the canonical fixture
  style. The generator fetches the live production style and rewrites every
  committable-host URL (sources, glyphs, sprites) into the
  `__E2E_MAP_BASE__/<host>/<path>` placeholder form; excluded hosts stay live
  in the style.
- `assets/**` — the vendored assets, keyed by host and path
  (`assets/<host>/<path>`, e.g. `assets/tile.ogis.app/…`, `assets/www.ogis.org/…`).
  Glyph directory names are URL-encoded.
- [`assets.manifest.json`](../tests/fixtures/map/assets.manifest.json) — every
  stored path with its byte count, source and zoom, plus the expected-but-absent
  (`204`/`404`) tiles. The manifest-completeness unit test asserts every padded
  demo-area tile is accounted for.

The set is served by the E2E-only Vite middleware
([`vitePlugin.mjs`](../tests/fixtures/map/vitePlugin.mjs)) under
`/__e2e_map__/**`, registered only when `VITE_E2E_FIXTURES=1` (set by
`playwright.config.js`'s webServer env). The context-level stub
([`mapAssets.js`](../tests/e2e/helpers/mapAssets.js)) serves the pinned style
with the placeholder substituted, serves Esri World Imagery a fast `404`, and
blocks any other external request.

**Degradation policy.** Missing tiles and glyph ranges degrade to an instant,
CORS-permissive empty `200`; a missing TileJSON descriptor gets a stub `tiles`
template that the middleware answers with empty `200`s. A missing sprite
returns `404` from the middleware, and a missing `style.json` fails loudly at
request time (the Playwright stub throws, pointing at
`npm run fixtures:refresh`) — drift is visible either way.

**Excluded sources.** `demoArea.mjs` lists the two sources deliberately not
vendored:

- `attribution` — metadata-only; declares no tiles or URL.
- `esri-satellite` — Esri World Imagery licensing excludes redistribution. Its
  URL stays live in the canonical style, but the E2E stub serves it a fast
  `404`, exercising the app's graceful-degradation path.

**Refresh workflow.** `npm run fixtures:refresh` runs
[`refresh.mjs`](../tests/fixtures/map/refresh.mjs), which fetches the live
style and, for each covered zoom, downloads the demo area padded by one tile
margin — plus glyphs and sprites — and rewrites the manifest. It is a manual
local step, deliberately **not** run in CI; run it when the upstream style
changes materially, review the diff and commit. `.prettierignore` excludes
`tests/fixtures/` (generated/vendored).

## Core terms

- **Instance** — one app context per page/iframe; `instanceId` comes from `?id=`
  (default `app`) and scopes persisted state. Keys are
  `ogis_{namespace}_{instanceId}`. See [Instances](./3.instances.md).
- **Feature** — a plain object with an `install(ctx)` method that registers a
  panel and/or corner chip from `src/main.js`. See [Features](./10.features.md).
- **`ogis.*` style properties** — GeoJSON feature properties that drive the
  `useGeoJSON` layers: `ogis.color`, `ogis.width`, `ogis.opacity`,
  `ogis.radius`, `ogis.fillOpacity`. See [GeoJSON](./6.geojson.md).
- **Map readiness signals** — `data-map-ready` (set at `style.load`) and the
  predicate-driven `data-map-idle`. See
  [Map — map readiness signals](./4.map.md#map-readiness-signals).
- **Cold-start country focus** — the timezone → raw browser language → random
  cascade that frames the map on a true cold start, overridable with
  `?country=`. See
  [Map — cold-start country focus](./4.map.md#cold-start-country-focus).

## CI and the trunk

The project follows **trunk-based development**: `master` is the only
long-lived branch (the project deliberately prefers it to `main`), changes land
as small Conventional Commits — direct pushes for the maintainer flow, pull
requests with the same advisory checks for contributions — and releases are cut
from the trunk automatically. The workflows themselves are documented in
[CI](./13.ci.md).

- **Release flow** — on a `master` push, `ci.yml` runs `release`
  (semantic-release) once `unit` and `commits` pass and `e2e` is `success` or
  `skipped`. A cut release writes the version bump and `CHANGELOG.md`, tags it
  and publishes the GitHub release; `deploy` then publishes GitHub Pages from the
  released SHA, and `heroes` regenerates the README imagery. If no commit
  warrants a release, nothing is cut and both follow-up jobs are skipped. See
  [CI — Releases with semantic-release](./13.ci.md#releases-with-semantic-release).
- **Matrix verification** — the committed matrix is checked by
  [`scripts/verify-matrix.js`](../scripts/verify-matrix.js), which compares
  decoded pixels rather than bytes: a file passes when every differing channel
  is within `--max-delta` (default `1`) and it differs in at most `--max-pixels`
  pixels (default `64`). Per-shard verification (`--mode shard`, the default)
  ignores committed files a shard did not capture; the aggregate `verify` job
  runs `--mode full`, which additionally requires a captured counterpart for
  every committed PNG and rejects extra captures.
- **Drift** — differences within the pixel tolerance: reported, passing, and
  never a trigger for the heal. A real change — more pixels, or a larger
  per-channel delta — fails verification, which on a scheduled or dispatched
  `master` run is what hands the matrix to the heal.
- **Heal (`refresh`)** — on a scheduled or manually dispatched `master` run
  whose aggregate verification moved, the `refresh` job rebuilds the committed
  baseline from that run's own six shard captures (validating the assembled
  set) and commits it as `github-actions[bot]`. Two guards defer the heal
  cleanly — the run stays green and the next scheduled run heals: an in-flight
  `ci.yml` run on `master`, and `master` having advanced past the run's SHA.
  There is no dispatched re-verification loop: the next run verifies.
- **Diff bundle** — when the matrix moves, the aggregate `verify` job builds a
  reviewable bundle
  ([`scripts/screenshot-diff-bundle.js`](../scripts/screenshot-diff-bundle.js)):
  per-file before/after/pixel-diff PNGs plus a self-contained `index.html`, a
  `summary.md` and a `report.json`. It ships as the `screenshots-diff-bundle`
  artefact and, for same-repository pull requests, is force-pushed to the
  `screenshots-diff` orphan branch (`pr-<n>/<run-id>/…`) and summarised in a
  sticky PR comment with inline images. Fork PRs get the artefact only.
- **Schedule vs dispatch** — [`screenshots.yml`](../.github/workflows/screenshots.yml)
  runs on pull requests, a daily schedule (07:30 UTC) and `workflow_dispatch` —
  never on pushes, so a matrix run can neither gate nor race a release. The
  scheduled and manually dispatched `master` runs are the heal path; pull
  requests never heal.
- **Green, where** — a `master` push is done when `ci.yml` verifies it: unit,
  Prettier format check, commit-message check and functional E2E. A pull
  request runs the same `ci.yml` checks plus the `Screenshots`
  workflow — a red matrix there is an advisory review signal, because no branch
  protection is configured. A scheduled or dispatched `Screenshots` run on
  `master` ends green when the matrix verifies, the heal lands, or the heal is
  cleanly deferred, and red only when the refresh fails or a moved matrix never
  reaches `refresh`.
