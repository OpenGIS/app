# Setup

Running, building, and configuring ogis.app.

---

## Commands

```bash
npm run dev          # start Vite dev server at http://localhost:5174
npm run build        # build the app to dist/
npm run test:unit    # run unit tests (< 10 s)
npm run test:e2e     # run all Playwright E2E tests
npm test             # alias for test:unit
```

---

## URL Parameters

The app reads three URL parameters on startup. These are primarily useful for embedding the app in an `<iframe>` with custom configuration.

| Parameter   | Purpose                                                        | Default            |
| ----------- | -------------------------------------------------------------- | ------------------ |
| `?id=`      | Instance ID — scopes `localStorage` keys                       | `app`              |
| `?locale=`  | Override UI language                                           | browser language   |
| `?country=` | Force the initial country focus — an alpha-2 code, or `random` | cold-start cascade |

`?country=` outranks both a `#map=` hash and any stored view; see [Map — cold-start country focus](./4.map.md#cold-start-country-focus).

**Examples:**

```
http://localhost:5174/?locale=fr
http://localhost:5174/?id=trip-planner&locale=en
```

The `?id=` parameter is only needed when embedding multiple ogis.app iframes on the same page so their localStorage keys don't collide. For normal single-page use the default `app` ID is correct.

---

## Entry Point

The app entry is `src/main.js`. It:

1. Reads `?id=` and `?locale=` URL params
2. Creates the Vue app and provides `ogisAppId`, `navigatorLocale`, `navigatorMessages`, etc.
3. Installs core features (Recordings, Offline Maps, Routes)
4. Mounts to `#app`

The HTML entry point is `index.html`, which loads `src/main.js` via `<script type="module" src="/src/main.js">`.

## Service worker

The app-shell worker (`public/sw.js`) is registered by `setupServiceWorker()` at the end of `src/main.js`. Registration is gated:

- **Production builds** register automatically.
- **Dev does not** — it unregisters any existing worker and clears the origin's caches instead, so a profile poisoned by an earlier dev registration self-heals.
- **`VITE_SW=1`** opts dev in (`VITE_SW=1 npm run dev`), which is how Playwright's webServer runs.

See [Offline — registration and gating](./12.offline.md#registration-and-gating) for why.

## iframe Embedding

The app supports embedded use via `<iframe>`. Each iframe has an independent JS context and therefore independent module-level state. The `?id=` parameter scopes `localStorage` keys so two iframes on the same page don't overwrite each other's saved view.

```html
<!-- Two independent map instances on one page -->
<iframe src="/index.html?id=map-a"></iframe>
<iframe src="/index.html?id=map-b"></iframe>
```

See [Instances](./3.instances.md) for the full localStorage key format.
