# Icons — sources, bundle and `icons:build`

The icon set is first-party. It was vendored from the now-archived [OpenGIS/icons](https://github.com/OpenGIS/icons) project (recovered at its final tag v0.3.0) and replaces the former `@ogis/icons` npm dependency. Authored sources live directly under [`src/icons/`](../src/icons/) (`svg/`, `png/`, `codepoints.json`), alongside the generated bundle, which is committed. See [Licence and provenance](#licence-and-provenance) for the full MIT notice.

---

## What lives where

| Path                                   | Role                                                                |
| -------------------------------------- | ------------------------------------------------------------------- |
| `src/icons/svg/*.svg`                  | Authored icons — the single source of truth (16 × 16 grid)          |
| `src/icons/png/*.png`                  | PNG masters traced to SVG by the build                              |
| `src/icons/codepoints.json`            | Persistent glyph → codepoint assignments                            |
| `src/icons/ogis-icons.svg`             | Generated SVG symbol sprite (`<symbol>` elements)                   |
| `src/icons/ogis-icons.woff2` / `.woff` | Generated icon font                                                 |
| `src/icons/ogis-icons.css`             | Generated font CSS: `@font-face` + `.oi-*` classes                  |
| `src/icons/ogis-icons.scss`            | Generated SCSS: `@font-face`, `.oi-*` classes and `$ogis-icons-map` |
| `src/icons/ogis-icons-variables.scss`  | Generated variables-only SCSS (`$ogis-icons-map`, no classes)       |
| `src/icons/ogis-icons.json`            | Generated name → codepoint map as JSON                              |

Everything here is committed — generated files included — so a fresh checkout builds and runs without the icon toolchain.

`npm run icons:build` regenerates the generated `ogis-icons*` files listed above; authored files are never deleted or renamed and are only ever updated in place by the documented trace, normalise and codepoint steps (see [Build](#build)).

## Build

```bash
npm run icons:build   # node scripts/icons.js
```

To add an icon, drop an `.svg` into `src/icons/svg/` (or a `.png` into `src/icons/png/`) and run `npm run icons:build`. The pipeline ([`scripts/icons.js`](../scripts/icons.js)):

1. **Trace PNGs** — every PNG in `src/icons/png/` is traced with Potrace and optimised with SVGO into `src/icons/svg/` (`processPngs`).
2. **Normalise** — every source SVG is scaled to a `0 0 16 16` viewBox in place (`normalizeSvgs`).
3. **Sprite** — all source SVGs are bundled into `ogis-icons.svg` with `svg-sprite` (`buildSprite`).
4. **Codepoints** — new names get the next free codepoint; `codepoints.json` is updated (`updateCodepoints`).
5. **Font + CSS** — `fantasticon` emits woff2/woff, CSS, SCSS and JSON (`buildFont`).
6. **Variables** — `ogis-icons-variables.scss` is written from the codepoint map (`buildVariablesScss`).

> [!NOTE]
> The build is **manual only** — it is not part of `npm run build` or CI. The generated bundle is committed so that ordinary builds never need the icon toolchain.

> [!WARNING]
> The build rewrites files under `src/icons/svg/` in place: PNG masters are re-traced and every source SVG is re-normalised. Check the diff after running `icons:build`.

## Codepoints

`src/icons/codepoints.json` is the source of truth and is deliberately append-only:

- Existing entries are never reassigned, so consumed codepoints stay stable across regenerations.
- New names are appended after the current maximum, starting from the base `0xf100`.
- The most recent additions are `map` (`U+F134`) and `waymark-logo` (`U+F135`).
- The orphan `logo` entry (`U+F114`) is intentionally retained from upstream even though no `logo.svg` exists. Do not delete it or reuse its codepoint for a new glyph.

## Naming conventions

| Thing             | Convention                 | Example                              |
| ----------------- | -------------------------- | ------------------------------------ |
| Font family       | `ogis-icons`               | `font-family: "ogis-icons"`          |
| Font CSS classes  | `oi-` prefix (fantasticon) | `.oi-position`, `class="oi-search"`  |
| SCSS map          | `$ogis-icons-map`          | `map-get($ogis-icons-map, "search")` |
| Sprite symbol ids | bare glyph name            | `#position`, `#file-arrow-down`      |

## How the app consumes the sprite

[`App.vue`](../src/App.vue#L3) imports the sprite as a raw string (`@/icons/ogis-icons.svg?raw`) and inlines it once in a hidden div at the root ([`App.vue:60`](../src/App.vue#L60)). Icons then reference symbols by id:

- [`icon.vue`](../src/components/ui/icon.vue#L24) renders `<svg :width :height :fill><use :href="#{name}" /></svg>` — the shared `Icon` component behind the corner chips, panel tabs and buttons.
- Imperative MapLibre markers use the same mechanism, e.g. [`useLocate.js:66`](../src/composables/useLocate.js#L66) injects `<svg><use href="#position"/></svg>`.

The font, CSS and SCSS outputs are generated for completeness, but the app does not import them — icon rendering is **sprite-only**.

## Generated-code policy

- [`.prettierignore`](../.prettierignore#L11) excludes `src/icons/`; `npm run format:check` never inspects icon sources or generated files. Do not hand-format them — regenerate instead.
- Never edit generated files by hand; `icons:build` overwrites them.
