# Theme

ogis.app uses a custom Bootstrap 5.3 theme built in SCSS with a green palette. The UI is intentionally muted and translucent so it blends with the map.

---

## How it works

`src/assets/sass/theme.scss` is the single source of truth for the visual style. It:

1. Imports Bootstrap's Sass functions
2. Declares palette variables that override Bootstrap's defaults
3. Imports the full Bootstrap component set
4. Applies ogis.app-specific overrides for the corner controls, panel, tabs, and form elements

---

## Palette

The four palette variables in `#2`:

```scss
$app-green: #39d353; // primary accent (buttons, links, active states)
$app-black: #111111; // near-black — dark UI surfaces (currently unreferenced)
$app-white: #ffffff; // light-mode panel background
$app-ink: #1a1f1a; // body text
```

These feed into Bootstrap's variable system — changing them automatically recolours buttons, links, badges, focus rings, and more.

---

## Bootstrap variable overrides

Any Bootstrap 5.3 variable can be overridden in `#3`, between the functions import and the infrastructure imports:

```scss
@import "bootstrap/scss/functions"; // #1 — must be first

// #2 palette + #3 Bootstrap overrides
$primary: $app-green;
$body-bg: $app-white;
$font-size-base: 0.9375rem; // 15 px (compact)

@import "bootstrap/scss/variables"; // #4
@import "bootstrap/scss/variables-dark";
@import "bootstrap/scss/maps";
@import "bootstrap/scss/mixins";
@import "bootstrap/scss/root";

// #5 Bootstrap components
// #6  App component overrides
```

Full list of Bootstrap variables: [Bootstrap 5.3 Sass variables source](https://github.com/twbs/bootstrap/blob/v5.3.8/scss/_variables.scss).

## Component overrides (`#6`)

### Corner controls (`.ogis-controls`)

The app has no navbar. Map chrome is a click-through overlay with four corner clusters, and every control is a chip. The chip is a frosted-glass pill so the map palette bleeds through:

```scss
.icon-btn--chip {
  padding: 0.4rem 0.7rem;
  border-radius: 999px;
  background: rgba(255, 255, 255, 0.82);
  backdrop-filter: blur(12px) saturate(160%);
  border: 1px solid rgba(0, 0, 0, 0.08);
  box-shadow: 0 1px 6px rgba(0, 0, 0, 0.12);
}
```

Dark mode swaps to the app's dark glass (`rgba(10, 18, 10, 0.82)`). The attribution chip additionally sets a max width and wraps its text (`.ogis-attribution-chip`), while its links are decoration only — `pointer-events: none` so any click opens the Info panel.

### Info panel (About, disclosures and attribution footer)

The About branding row pairs the tagline with the OGIS logo, sized by `.ogis-about-logo { height: 44px; width: auto }`.

Privacy uses a native `<details>` element. The `.ogis-disclosure > summary` rule hides the browser marker and renders a `[+]` / `[−]` toggle in the primary colour, while the `.ogis-disclosure-more` / `.ogis-disclosure-less` spans swap the summary label between "Read more" and "Read less" from the `[open]` state.

The Info panel content fills the scroll container (`.ogis-info-panel { min-height: 100% }`), so the attribution block (`.ogis-attribution-section`) — an unheaded footer — can sit flush at the panel's bottom edge. Its `margin-top: auto` pushes it down when content is short, and `position: sticky; bottom: 0` (with the panel's frosted glass) keeps it pinned there while overflowing content scrolls behind it:

```scss
.ogis-info-panel {
  min-height: 100%;
}

.ogis-attribution-section {
  margin-top: auto;
  position: sticky;
  bottom: 0;
  z-index: 2;
  background: rgba(255, 255, 255, 0.92);
  backdrop-filter: blur(20px) saturate(160%);
  -webkit-backdrop-filter: blur(20px) saturate(160%);
}

[data-bs-theme="dark"] .ogis-attribution-section {
  background: rgba(10, 18, 10, 0.92);
}
```

Its links are interactive (`--bs-primary`), unlike the attribution chip's decoration-only links.

### Side panel (`.ogis-panel`)

Semi-transparent background so the map remains visible behind the panel:

```scss
.offcanvas.ogis-panel {
  --bs-offcanvas-bg: rgba(255, 255, 255, 0.82);
  backdrop-filter: blur(20px) saturate(160%);
  border-right: 1px solid rgba(0, 0, 0, 0.07) !important;
  box-shadow: 3px 0 28px rgba(0, 0, 0, 0.08);
}

[data-bs-theme="dark"] .ogis-panel {
  --bs-offcanvas-bg: rgba(10, 18, 10, 0.82);
  border-right: 1px solid rgba(255, 255, 255, 0.07) !important;
  box-shadow: 3px 0 28px rgba(0, 0, 0, 0.4);
}
```

Panel width is controlled via a CSS custom property, capped on small screens so a tappable strip of dismiss backdrop always remains beside the panel. `.offcanvas.ogis-panel` applies it as `width`; the compound selector is deliberate — it out-specifies Bootstrap's `.offcanvas.offcanvas-start`:

```scss
:root {
  --ogis-panel-width: min(340px, calc(100vw - 4rem));
}
```

Where there is room the `min()` resolves to the full `$offcanvas-horizontal-width` (340 px), so desktop stays exactly 340 px; a 320 px phone gets 256 px and a 390 px phone 326 px.

### Mobile safe areas

`index.html` already opts into edge-to-edge rendering (`viewport-fit=cover` and a `black-translucent` status bar). `:root` exposes the browser's insets as custom properties so app CSS — and tests — can consume them:

```scss
:root {
  --ogis-safe-top: env(safe-area-inset-top, 0px);
  --ogis-safe-right: env(safe-area-inset-right, 0px);
  --ogis-safe-bottom: env(safe-area-inset-bottom, 0px);
  --ogis-safe-left: env(safe-area-inset-left, 0px);
}
```

- `.ogis-root` — the fixed full-viewport shell ([`App.vue`](../src/App.vue)) uses the `vh-100` utility (`height: 100vh`) rather than `h-100` (`height: 100%`). On installed iOS PWAs with `viewport-fit=cover`, WebKit reports percentage heights short by the bottom safe-area inset ([WebKit bug #254868](https://bugs.webkit.org/show_bug.cgi?id=254868)), leaving a strip beneath the map; `vh` units include the safe areas in standalone mode. This is a standard CSS unit — no iOS or user-agent detection — and `100vh` matches the previous `100%` behaviour everywhere else (desktop, browser tabs, Android, iframes).
- `.offcanvas.ogis-panel` maps top/bottom/left to `padding-*`, keeping panel content clear of the status bar and home indicator.
- `.ogis-corner` adds each inset to its per-side padding (`calc(0.75rem + var(--ogis-safe-*))`), so the corner chips clear notches, status bars and the home indicator at every edge.

### Icon buttons (`.icon-btn`)

Inactive icons use `--bs-secondary-color`. The active panel state and hover use `--bs-primary` with a 0.15 s ease transition. The `[aria-pressed="true"]` rule must live in section `#6e`:

```scss
.icon-btn {
  &[aria-pressed="true"] {
    color: var(--bs-primary);
  }
  &:hover {
    color: var(--bs-primary);
  }
}
```

The chip variant (`.icon-btn--chip`) also lightens its glass background on hover/active and has a dark-theme override (`rgba(10, 18, 10, …)` background, `rgba(255, 255, 255, 0.55)` inactive icon colour).

### MapLibre scale bar

MapLibre's `ScaleControl` sits above the bottom-left attribution chip, so the control's bottom offset is raised:

```scss
.maplibregl-ctrl-bottom-left {
  bottom: 3.25rem !important;
}
```

On narrow screens (`max-width: 767.98px`) the expanded pill can wrap to two lines, so a media query raises the offset to `4.5rem`; the collapsed-state rule below still takes precedence.

Once the chip collapses to the icon-only pill on the first map drag, the chip sets `data-attrib-collapsed="true"` on `.ogis-root` (driven by [`useAttribution`](../src/composables/useAttribution.js) in [`App.vue`](../src/App.vue)) and the scale moves inline to the right of the ⓘ icon:

```scss
.ogis-root[data-attrib-collapsed="true"] .maplibregl-ctrl-bottom-left {
  bottom: 0.6rem !important;
  left: 3.5rem !important;
}
```

In dark mode MapLibre's scale control would otherwise remain a bright white box, so it is recoloured to the app's dark glass (background, border and text only — geometry untouched):

```scss
[data-bs-theme="dark"] .maplibregl-ctrl-scale {
  background-color: rgba(10, 18, 10, 0.82);
  border-color: rgba(255, 255, 255, 0.1);
  color: rgba(255, 255, 255, 0.7);
}
```

### Dark mode

Bootstrap 5.3's `data-bs-theme` system is fully supported. The app has no in-app toggle and stores no theme preference — it always follows the operating system/browser `prefers-color-scheme` setting:

- [`useSettings`](../src/composables/useSettings.js) derives the module-level `resolvedTheme` (`'light'` or `'dark'`) and `isDark` from a `matchMedia('(prefers-color-scheme: dark)')` change listener, so runtime OS changes apply immediately.
- `useSettings` itself applies the theme to `<html>` — `document.documentElement.setAttribute("data-bs-theme", theme)` — via an immediate `watch`, the single DOM application point. The watch is browser-guarded, so importing the module outside a DOM environment is safe.
- It targets the document root rather than `.ogis-root` because modals are [teleported to `<body>`](../src/components/modals/modal.vue), outside the app root; from there they inherit Bootstrap's dark variables instead of resolving the light `:root` defaults. `.ogis-root` keeps only `data-attrib-collapsed` (see [`App.vue`](../src/App.vue)).
- `useSettings` also emits `theme:change` (`'dark'` / `'light'`) on the shared emitter when the system preference changes. It has no consumers yet — reserved for future map style integration.

Because the attribute is on `<html>`, the `[data-bs-theme="dark"] .ogis-*` overrides in `theme.scss` — and the examples throughout this doc — still match. ogis.app-specific overrides include dark variants for the panel, corner chips, the Info attribution footer and the MapLibre scale control.
