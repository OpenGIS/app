# Theme

ogis.app uses a single **default** theme: a custom Bootstrap 5.3 theme built in SCSS with a green accent and a dark palette. The palette is compiled into the base `:root`, so the UI always renders the same way regardless of the operating system or browser colour-scheme preference. The UI is intentionally muted and translucent so it blends with the map.

---

## How it works

`src/assets/sass/theme.scss` is the single source of truth for the visual style. It:

1. Imports Bootstrap's Sass functions
2. Declares the app palette and the Bootstrap variables the theme changes
3. Imports Bootstrap's infrastructure, then compiles Bootstrap's dark palette into the base root
4. Imports the full Bootstrap component set
5. Applies ogis.app-specific overrides for the corner controls, panel, tabs and form elements

The theme identity is `data-theme="default"` on `<html>` ([`index.html`](../index.html)). `meta[name="color-scheme"]` and an inline boot style paint the first frame dark before the CSS bundle loads, and the compiled `:root` declares `color-scheme: dark` for native controls. There is no `data-bs-theme` attribute at runtime and no runtime theme switching.

---

## Palette

The palette is one accent value, in `#2`:

```scss
$app-green: #39d353; // GPS marker green — primary accent
```

It feeds Bootstrap's variable system, so changing it recolours buttons, links, badges, focus rings and the other components that derive from `$primary`.

Surfaces come from Bootstrap's dark palette rather than app-specific colour variables: `$body-bg-dark` resolves to `#212529`. The corner and panel glass values are declared locally where they are used.

---

## Bootstrap overrides

The variable overrides in `#3` are deliberately small:

```scss
$primary: $app-green;

$offcanvas-horizontal-width: 340px;
$offcanvas-transition-duration: 0.25s;

$font-size-base: 0.9375rem; // 15 px (compact)
```

### Dark palette as the base

Bootstrap's dark palette is compiled as the unconditional default rather than as an opt-in `[data-bs-theme="dark"]` block. In `#4`, after `variables` and `variables-dark` are imported, the scalar `*-dark` values are copied onto their base variables:

```scss
$body-color: $body-color-dark;
$body-bg: $body-bg-dark;
$border-color: $border-color-dark;
$link-color: $link-color-dark;
// …the remaining scalar *-dark remaps
```

Bootstrap bakes some values into data URIs and roots before `maps` is imported, so those are remapped before the maps:

```scss
$accordion-button-icon: $accordion-button-icon-dark;
$form-select-indicator: $form-select-indicator-dark;
$carousel-indicator-active-bg: $carousel-indicator-active-bg-dark;
// …the remaining pre-map remaps
```

After `maps`, the dark maps for text, subtle backgrounds and subtle borders are merged into their base maps. `$enable-dark-mode` is disabled **after** those merges — it must stay after `maps`, because the dark maps have to exist before Bootstrap is told not to emit its own dark-mode block:

```scss
@import "bootstrap/scss/maps";

$theme-colors-text: map-merge($theme-colors-text, $theme-colors-text-dark);
// …bg-subtle and border-subtle merges

// MUST stay after maps: the dark maps must exist before disabling dark mode
$enable-dark-mode: false;
```

`color-scheme: dark` is set on the base `:root`, so scrollbars, form controls and other UA-rendered surfaces are dark from the first paint. Because dark mode is disabled at compile time, Bootstrap generates no `[data-bs-theme="dark"]` block; app overrides are ordinary base selectors.

Full list of Bootstrap variables: [Bootstrap 5.3 Sass variables source](https://github.com/twbs/bootstrap/blob/v5.3.8/scss/_variables.scss).

---

## Default theme

The theme is called **default**. Its identity is the `data-theme="default"` attribute on `<html>` in [`index.html`](../index.html); no application code reads or writes that attribute at runtime, and there is no `data-bs-theme` attribute. The dark palette is compiled into the base `:root` (see [Dark palette as the base](#dark-palette-as-the-base)), so the app renders identically whatever the OS or browser prefers.

The first frame is dark before any bundle loads: `meta[name="color-scheme"]` is `dark`, and an inline style gives `html` a `#212529` background. `:root` then declares `color-scheme: dark`, so native controls and scrollbars match.

There is no runtime theme switching and no stored theme preference; [`useSettings`](../src/composables/useSettings.js) is units-only and has no theme logic. A future theme would be added as a `[data-theme="…"]` override layered over the base `:root` palette and selected by the document's `data-theme` attribute; the default theme needs no such override. Adding a switcher is out of scope until one exists.

## Component overrides (`#6`)

### Corner controls (`.ogis-controls`)

The app has no navbar. Map chrome is a click-through overlay with four corner clusters, and every control is a chip. A chip is a 72 px frosted-glass circle — the icon above a short monospace uppercase label — with its tunable levers exposed as custom properties so the map palette bleeds through:

```scss
.icon-btn--chip {
  --ogis-chip-diameter: 72px;
  --ogis-chip-icon-size: 29px;
  --ogis-chip-gap: 0.25rem;
  --ogis-chip-label-min: 8px;
  --ogis-chip-label-max: 11px;
  --ogis-chip-label-target: 62%;

  background: rgba(10, 18, 10, 0.82);
  backdrop-filter: blur(12px) saturate(160%);
  border: 1px solid rgba(255, 255, 255, 0.1);
  box-shadow: 0 1px 6px rgba(0, 0, 0, 0.12);
  color: rgba(255, 255, 255, 0.7);
}
```

The round geometry covers the menu, locate and feature chips, and the attribution chip once collapsed; the expanded attribution chip keeps its pill shape so the credits text can wrap inline:

```scss
.icon-btn--chip:not(.ogis-attribution-chip),
.ogis-root[data-attrib-collapsed="true"] .ogis-attribution-chip {
  width: var(--ogis-chip-diameter);
  height: var(--ogis-chip-diameter);
  border-radius: 50%;
  flex-direction: column;
  justify-content: center;
  gap: var(--ogis-chip-gap);
}
```

Chip labels are sized at runtime by [`useFitText`](../src/composables/useFitText.js), which reads the label levers back off the chip and scales the text between min and max (see [UI — fitted chip labels](./5.ui.md#fitted-chip-labels--usefittext)). A mount overrides the levers per chip via `IconButton`'s chip-only props (`iconSize`, `iconGap`, `labelMin`, `labelMax`, `labelTarget`): they render as inline custom properties on the button, and inline values beat the class defaults — the locate chip, for example, uses a larger icon and a tighter label target than the menu chip.

The chips use the app's dark glass (`rgba(10, 18, 10, 0.82)`) throughout. The expanded attribution chip additionally sets a max width and wraps its credits (`.ogis-attribution-chip`), while its links are decoration only — `pointer-events: none` so any click opens the Info panel. The menu chip's `.ogis-menu-badge` is an 8 px generic status dot in the chip's top-right corner; no installed feature currently raises the signal, so only the shared shape and a state variant are styled. Navigation status has its own top-centre `.ogis-nav-control`, a full-size frosted-glass card (`data-variant="card"`, with compact `chip` and `pill` variants defined by the theme) and a max width that keeps it clear of the menu and locate chips. The navigation connector is a fixed, full-viewport SVG overlay (`.ogis-nav-connector`) above the map canvas, so terrain and 3D buildings cannot occlude its 3 px green dashed polyline (`var(--bs-primary)` = `#39d353`, `stroke-dasharray: 6 6`, butt caps). The badge, the navigation control and the connector are `pointer-events: none`.

### Info panel (About, disclosures and attribution footer)

The About branding row pairs the tagline with a sprite `ogis-logo` mark inside the 44 × 44 dark tile (`.ogis-about-logo`).

Privacy uses a native `<details>` element, styled as a compact pinned bar: a two-row grid places the title and a two-line-clamped summary beside the sprite disclosure icon (`.ogis-privacy-bar__icon` — `plus` collapsed, `dash` expanded; the accent is `--ogis-privacy-accent` = `#39d353`). The icon is decorative (`aria-hidden`), so `<summary>` alone carries the expanded state for assistive technology. The body holds the two sub-sections — on-device storage and third-party sources — and stays in the DOM while collapsed; its height is capped at `min(40vh, 20rem)` with internal scrolling, so an expanded footer can never outgrow a short viewport.

The Info panel content fills the scroll container (`.ogis-info-panel { min-height: 100% }`), and the Privacy bar and attribution footer share one pinned surface (`.ogis-info-footer`) — an unheaded footer that sits flush at the panel's bottom edge. Its `margin-top: auto` pushes it down when content is short, and `position: sticky; bottom: 0` (with its own frosted-glass surface) keeps it pinned there while overflowing content scrolls behind it. A single sticky wrapper avoids two stacked siblings both resolving to `bottom: 0` and doubling the glass blur:

```scss
.ogis-info-panel {
  min-height: 100%;
}

.ogis-info-footer {
  margin-top: auto;
  position: sticky;
  bottom: 0;
  z-index: 2;
  background: rgba(10, 18, 10, 0.92);
  backdrop-filter: blur(20px) saturate(160%);
  -webkit-backdrop-filter: blur(20px) saturate(160%);
}
```

The footer's attribution links are interactive (`--bs-primary`), unlike the attribution chip's decoration-only links, and the attribution section keeps its own `border-top` as a separator below the Privacy bar.

### Side panel (`.ogis-panel`)

Semi-transparent background so the map remains visible behind the panel:

```scss
.offcanvas.ogis-panel {
  --bs-offcanvas-bg: rgba(10, 18, 10, 0.82);
  backdrop-filter: blur(20px) saturate(160%);
  border-right: 1px solid rgba(255, 255, 255, 0.07) !important;
  box-shadow: 3px 0 28px rgba(0, 0, 0, 0.4);
}
```

Panel width is controlled via a CSS custom property, capped on small screens so a tappable strip of dismiss backdrop always remains beside the panel. `.offcanvas.ogis-panel` applies it as `width`; the compound selector is deliberate — it out-specifies Bootstrap's `.offcanvas.offcanvas-start`:

```scss
:root {
  --ogis-panel-width: min(340px, calc(100vw - 4rem));
}
```

Where there is room the `min()` resolves to the full `$offcanvas-horizontal-width` (340 px), so desktop stays exactly 340 px; a 320 px phone gets 256 px and a 390 px phone 326 px.

### Mobile safe areas

`index.html` keeps the `black-translucent` status bar but deliberately omits `viewport-fit=cover`: on iOS 26.5.2 installed web apps, cover made WebKit address a viewport short by the top safe-area inset, leaving an unpaintable dark strip at the bottom of the screen (confirmed on an iPhone 16). `:root` exposes the browser's insets as custom properties so app CSS — and tests — can consume them:

```scss
:root {
  --ogis-safe-top: env(safe-area-inset-top, 0px);
  --ogis-safe-right: env(safe-area-inset-right, 0px);
  --ogis-safe-bottom: env(safe-area-inset-bottom, 0px);
  --ogis-safe-left: env(safe-area-inset-left, 0px);
}
```

- `.ogis-root` — the fixed full-viewport shell ([`App.vue`](../src/App.vue)) uses the `h-100` utility (`height: 100%`). Percentage height resolves against the initial containing block — the visible viewport — which is correct in browser modes; `vh` would resolve to the large viewport and push bottom UI underneath Safari's floating toolbar. Full-screen rendering on installed iOS PWAs comes from the viewport meta omitting `viewport-fit=cover` (see above), not from viewport units.
- `.offcanvas.ogis-panel` maps top/bottom/left to `padding-*`, keeping panel content clear of the status bar and home indicator.
- `.ogis-corner` adds each inset to its per-side padding (`calc(0.75rem + var(--ogis-safe-*))`), so the corner chips clear notches, status bars and the home indicator at every edge.

### Icon buttons (`.icon-btn`)

Inactive icons use `rgba(255, 255, 255, 0.55)`; the active state uses `--bs-primary` with a 0.15 s ease colour transition. Hover styling is deliberately not used, so button visuals reflect true state only, consistently across pointer and touch devices. The `[aria-pressed="true"]` rule is the only state rule, and it must live in section `#6e`:

```scss
.icon-btn {
  color: rgba(255, 255, 255, 0.55);
  transition: color 0.15s ease;

  &[aria-pressed="true"] {
    color: var(--bs-primary);
  }
}
```

The chip variant (`.icon-btn--chip`) uses the app's dark glass (`rgba(10, 18, 10, 0.82)` background, `rgba(255, 255, 255, 0.7)` inactive icon colour) and lightens its background to `rgba(10, 18, 10, 0.92)` while active.

> [!NOTE]
> Hover styling is intentionally not used anywhere: button visuals reflect true state only, so pointer and touch devices render consistently — and touch hover is unreliable anyway, because a tap latches `:hover` (there is no mouseout). Bootstrap's own `.btn:hover` rules are not capability-gated either, so an unconditional `.btn:hover:not(:active)` reset at the top of `#6` restores the resting look on every device; the `:not(:active)` guard keeps Bootstrap's momentary press feedback while a button is actually pressed. The modal close control is `.ogis-modal-close` with the sprite `x` icon and an explicit `:focus-visible` outline; it has no hover rule, consistent with the no-hover policy.

### MapLibre scale bar

By default MapLibre's `ScaleControl` sits above the bottom-left attribution chip, so the control's bottom offset is raised:

```scss
.maplibregl-ctrl-bottom-left {
  bottom: 3.25rem !important;
}
```

On narrow screens (`max-width: 767.98px`) the expanded pill can wrap to two lines, so a media query raises the offset to `4.5rem`; the collapsed-state rule below still takes precedence.

While the chip is collapsed — whenever the Info pane is open, and permanently after the first map drag — `data-attrib-collapsed="true"` is set on `.ogis-root` (driven by [`useAttribution`](../src/composables/useAttribution.js) in [`App.vue`](../src/App.vue)) and the scale moves inline to the right of the ⓘ icon:

```scss
.ogis-root[data-attrib-collapsed="true"] .maplibregl-ctrl-bottom-left {
  bottom: 0.6rem !important;
  left: 4.75rem !important;
}
```

MapLibre's scale control ships as a bright white box, which stands out against the default dark palette, so it is recoloured to the app's dark glass (background, border and text only — geometry untouched):

```scss
.ogis-root .maplibregl-ctrl-scale {
  background-color: rgba(10, 18, 10, 0.82);
  border-color: rgba(255, 255, 255, 0.1);
  color: rgba(255, 255, 255, 0.7);
}
```

The rule is scoped to `.ogis-root` so it wins by specificity regardless of CSS bundle order.
