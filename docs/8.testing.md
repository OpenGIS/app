# Testing

On Route has two test layers:

- **Unit tests** (Vitest) — test pure composable logic in milliseconds
- **E2E tests** (Playwright) — test full browser integration

```bash
npm run test:unit                                     # Vitest — < 10 s
npm run test:e2e -- tests/e2e/core.spec.js --workers=1 # single spec (1–3 min)
npm run test:e2e -- --workers=1                       # full E2E suite (manual run)
npm test                                              # unit tests only (final check)
```

- Unit tests complete in under 10 seconds — run `npm test` as the final check on every change.
- Run E2E locally with `--workers=1`. The default parallel workers (3 on this machine) cause flaky input-dispatch hangs with software-rendered MapLibre (SwiftShader); serial is both reliable and faster. Prefer targeted single-spec runs while developing; the full suite is a longer manual run.
- E2E does not run in CI — CI runs Vitest only.
- `playwright.config.js` sets no `actionTimeout` override. A tight bound was tried and reverted because software-rendered (SwiftShader) actionability stalls can exceed several seconds under load, causing false failures. Actions therefore fall back to Playwright's default bound (the test timeout).

## Unit tests

Unit tests live in `tests/unit/` and cover pure, extractable logic from composables, features, stores and the API client:

| `tests/unit/useUI.test.js` | `useUI.js` | Breakpoints, panel/nav state, first load, instance isolation |
| `tests/unit/useLocale.test.js` | `useLocale.js` | `matchLocale()` script-prefix matching, locale resolution, `navigator.languages` walk, `languagechange`, `documentElement.lang` sync, glob-loaded locales, `t()`, mapLanguageTag |
| `tests/unit/useSettings.test.js` | `useSettings.js` | `localeDefaultUnits()` mapping, OS-derived units, system theme resolution, `theme:change` |
| `tests/unit/useGeoJSON.test.js` | `useGeoJSON.js` | Feature CRUD, style defaults, colour assignment, instance isolation |
| `tests/unit/routes-gpx.test.js` | `features/routes/gpx.js` | GPX parsing: tracks, routes, names, namespaced documents, robustness |
| `tests/unit/offline-tiles.test.js` | `features/offline/tiles.js` | Tile maths: lon/lat → tile, bounds → range, enumeration, URL templates |
| `tests/unit/offline-download.test.js` | `features/offline/download.js` | Region URL building and per-region URL sets |
| `tests/unit/apiClient.test.js` | `api/client.js` | Axios client for credentialed SPA auth, CSRF cookie handling |
| `tests/unit/syncStore.test.js` | `stores/syncStore.js` | Offline sync queue: enqueue, failures, completion |
| `tests/unit/useAuthSession.test.js` | `composables/auth/useAuthSession.js` | Session load and auth state |
| `tests/unit/useMagicLinkAuth.test.js` | `composables/auth/useMagicLinkAuth.js` | Magic-link request flow |
| `tests/unit/useCollectionsBrowser.test.js` | `composables/resources/useCollectionsBrowser.js` | Collections listing and metadata updates |
| `tests/unit/useMapsBrowser.test.js` | `composables/resources/useMapsBrowser.js` | Maps listing, opening, GeoJSON rendering |
| `tests/unit/useResourceApis.test.js` | `composables/resources/useMapsApi.js`, `useCollectionsApi.js` | Resource API request shaping |
| `tests/unit/useResourceOverview.test.js` | `composables/resources/useResourceOverview.js` | Map + collection overview for the account panel |

> [!NOTE]
> The auth, resource and sync tests cover the backend-dependent features that are currently commented out of `src/main.js` — their modules remain in the codebase and are tested, ready for re-enablement.

When adding new composable logic, consider whether it can be tested as a pure function. If so, add a unit test in `tests/unit/`.

## Running a specific E2E spec

Run E2E serially with `--workers=1` (see the timing guidance above). Narrow further with `--grep`:

```bash
npm run test:e2e -- tests/e2e/core.spec.js --workers=1
npm run test:e2e -- tests/e2e/core.spec.js --grep "About panel" --workers=1
```

## E2E structure

E2E specs live in `tests/e2e/` and test behaviour in the real browser:

```
tests/
  unit/                    ← Vitest unit tests
  e2e/
    core.spec.js           ← core UI: first load, about, privacy
    features/
      locate.spec.js       ← GPS locate
      recordings.spec.js   ← recordings feature
      routes.spec.js       ← GPX routes: import, delete, navigate
      settings.spec.js     ← settings, theme, OS-derived units + language
      offline.spec.js      ← offline region download
      account.spec.js      ← skipped (feature disabled in src/main.js)
      collections.spec.js  ← skipped (feature disabled)
      maps.spec.js         ← skipped (feature disabled)
    screenshots/
      readme.spec.js       ← assets/screenshots/app-preview.png
```

> [!NOTE]
> `account`, `collections` and `maps` specs are marked `test.describe.skip` while their features are commented out in `src/main.js` (lines 16–20, 113–116). Remove the skip when the features ship.

## Writing E2E tests

```js
import { test, expect } from "@playwright/test";

test.describe("My feature / My heading", () => {
  test("does the thing", async ({ page }) => {
    await page.goto("/");
    await expect(page.locator(".my-element")).toBeVisible();
  });
});
```

- Use `page.addInitScript` to seed `localStorage` before navigation
- Storage keys: `onrte_{namespace}_{instanceId}` — the default id is `'app'`, so the view key is `onrte_view_app`
- Settings are OS-derived and write nothing — there is no `onrte_settings_*` key to seed or assert
- Poll for throttled async side-effects with `expect.poll()` rather than `waitForTimeout`

## Screenshots

Screenshots are captured by Playwright and live in `assets/screenshots/`. To regenerate:

```bash
npm run test:e2e -- tests/e2e/screenshots/readme.spec.js
```

Screenshots are committed to the repository so docs render correctly on GitHub.

**Conventions:**
- Full viewport at **1280×720** (desktop) unless illustrating a specific breakpoint
- Test names describe the UI state being captured
- Add a screenshot when the visual output meaningfully illustrates the behaviour
