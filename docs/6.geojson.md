# GeoJSON — `useGeoJSON`

`useGeoJSON` provides a simple interface for rendering GeoJSON features on the map. It manages a single shared MapLibre source and data-driven style layers for points, lines, polygons and direction chevrons — you never call `addSource`, `addLayer`, or `setData` directly.

Features set before the map is ready are queued and applied automatically on `map:ready`. Sources and layers are cleaned up on `destroy`.

> [!NOTE]
> GeoJSON is the transient render projection for track data, not its stored
> form. Routes, recordings and waypoint documents are persisted as versioned
> track documents; `ogis.*` properties such as `ogis.color` and
> `ogis.direction` only affect rendering. See [Tracks](./15.tracks.md).

---

## Quick start

```js
import { useGeoJSON } from "@/composables/useGeoJSON.js";

const geoJSON = useGeoJSON();
geoJSON.setFeature({
  type: "Feature",
  id: "pin",
  geometry: { type: "Point", coordinates: [-0.1278, 51.5074] },
  properties: {},
});
```

From a feature `install()` function, pass `instanceId` explicitly:

```js
const geoJSON = useGeoJSON(instanceId);
```

## API

### `setFeature(feature)`

Add or update a GeoJSON feature. The feature must have a top-level `id`.

```js
geoJSON.setFeature({
  type: "Feature",
  id: "track",
  geometry: {
    type: "LineString",
    coordinates: [
      [-0.1278, 51.5074],
      [-0.1225, 51.512],
    ],
  },
  properties: {
    "ogis.color": "#39d353",
    "ogis.width": 4,
    "ogis.opacity": 0.9,
  },
});
```

Calling `setFeature` with the same `id` replaces the existing feature.

Supported geometry types: `Point`, `MultiPoint`, `LineString`, `MultiLineString`, `Polygon`, `MultiPolygon`.

### `removeFeature(id)`

```js
geoJSON.removeFeature("track");
```

### `clearFeatures()`

```js
geoJSON.clearFeatures();
```

### `setDefaults(defaults)`

Set default style values. Affects all future `setFeature()` calls and immediately re-renders existing features that have no explicit style property.

```js
geoJSON.setDefaults({
  line: { color: "#39d353", width: 4, opacity: 0.9 },
  point: { radius: 8 },
  polygon: { fillOpacity: 0.3 },
});
```

## Style properties

Style is driven by `ogis.*` properties on the GeoJSON feature.

### All types

| Property       | Default                        | Description        |
| -------------- | ------------------------------ | ------------------ |
| `ogis.color`   | auto-assigned bright           | Fill/stroke colour |
| `ogis.opacity` | 0.85 (line/polygon), 1 (point) | Layer opacity      |

### Lines

| Property         | Default | Description                                      |
| ---------------- | ------- | ------------------------------------------------ |
| `ogis.width`     | 3       | Line width                                       |
| `ogis.direction` | off     | `true` renders direction chevrons along the line |

Line layers always use `round` cap and join.

### Direction chevrons

Set `ogis.direction: true` on a line feature to render static direction
chevrons along the geometry. The arrow points in the direction of the line's
point order — timestamps and bearing data are not consulted.

### Points

| Property      | Default |
| ------------- | ------- |
| `ogis.radius` | 6       |

Points are rendered as circles with a 1.5 px white stroke.

### Polygons

| Property           | Default |
| ------------------ | ------- |
| `ogis.fillOpacity` | 0.4     |

Polygons get a fill layer (`ogis.fillOpacity`) and an outline layer (`ogis.opacity`).

---

## Auto-assigned colours

When a feature has no `ogis.color`, `useGeoJSON` assigns a persistent random colour from a set of visually distinct bright primaries. The same colour is reused for all updates to that feature ID and released on remove/clear.

---

## How it works

A single MapLibre source (`ogis-geojson`) holds a `FeatureCollection`. Five
style layers are set up once on `map:ready` — the direction layer only when the
chevron image can be registered:

| Layer ID                       | Type     | Filters                                                |
| ------------------------------ | -------- | ------------------------------------------------------ |
| `ogis-geojson-polygon-fill`    | `fill`   | Polygon, MultiPolygon                                  |
| `ogis-geojson-polygon-outline` | `line`   | Polygon, MultiPolygon                                  |
| `ogis-geojson-line`            | `line`   | LineString, MultiLineString                            |
| `ogis-geojson-point`           | `circle` | Point, MultiPoint                                      |
| `ogis-geojson-direction`       | `symbol` | LineString/MultiLineString with `ogis.direction: true` |

All style properties are data-driven via MapLibre expressions on `ogis.*` feature properties. All layers and the source are removed when the app is destroyed.

### Direction arrow rendering

The chevron is a procedural 64 × 64 canvas image — a white arrow with a dark
outline — registered once with `map.addImage` at `pixelRatio: 2`. It has no SDF,
sprite sheet or external asset dependency. The artwork points up, so
`icon-rotate: 90` aligns it with the local line tangent; `icon-rotation-alignment`
and `icon-pitch-alignment` are both `map`, and `icon-keep-upright` is `false` so
the arrow follows the line bearing rather than the viewport.

The symbols are static, spaced every 110 px (`symbol-spacing`), scaled by zoom
(0.35 at z8 up to 0.9 at z20) and painted at 0.7 opacity. Collision detection is
left on (`icon-allow-overlap: false`, `icon-ignore-placement: false`), so map
labels and other symbols take precedence. If canvas or `map.addImage` is
unavailable, the direction layer is skipped; the other layers still render.
