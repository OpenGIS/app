# Theme

On Route uses a custom Bootstrap 5.3 theme built in SCSS with a green palette. The UI is intentionally muted and translucent so it blends with the map.

---

## How it works

`src/assets/sass/theme.scss` is the single source of truth for the visual style. It:

1. Imports Bootstrap's Sass functions
2. Declares palette variables that override Bootstrap's defaults
3. Imports the full Bootstrap component set
4. Applies On Route-specific overrides for the corner controls, panel, tabs, and form elements

---

## Palette

The four palette variables in `#2`:

```scss
$app-green: #39d353; // primary accent (buttons, links, active states)
$app-black: #111111; // near-black — dark UI surfaces (currently unreferenced)
$app-white: #ffffff; // light-mode panel background
$app-ink: #1a1f1a; // body text
```

These feed into Bootstrap's variable system — changing them automatically recolours buttons, links, badges, focus rings, and more.

---

## Bootstrap variable overrides

Any Bootstrap 5.3 variable can be overridden in `#3`, between the functions import and the infrastructure imports:

```scss
@import "bootstrap/scss/functions"; // #1 — must be first

// #2 palette + #3 Bootstrap overrides
$primary: $app-green;
$body-bg: $app-white;
$font-size-base: 0.9375rem; // 15 px (compact)

@import "bootstrap/scss/variables"; // #4
@import "bootstrap/scss/variables-dark";
@import "bootstrap/scss/maps";
@import "bootstrap/scss/mixins";
@import "bootstrap/scss/root";

// #5 Bootstrap components
// #6 On Route component overrides
```

Full list of Bootstrap variables: [Bootstrap 5.3 Sass variables source](https://github.com/twbs/bootstrap/blob/v5.3.8/scss/_variables.scss).

## Component overrides (`#6`)

### Corner controls (`.onrte-controls`)

The app has no navbar. Map chrome is a click-through overlay with four corner clusters, and every control is a chip. The chip is a frosted-glass pill so the map palette bleeds through:

```scss
.icon-btn--chip {
  padding: 0.4rem 0.7rem;
  border-radius: 999px;
  background: rgba(255, 255, 255, 0.82);
  backdrop-filter: blur(12px) saturate(160%);
  border: 1px solid rgba(0, 0, 0, 0.08);
  box-shadow: 0 1px 6px rgba(0, 0, 0, 0.12);
}
```

Dark mode swaps to the app's dark glass (`rgba(10, 18, 10, 0.82)`). The attribution chip additionally sets a max width and wraps its text (`.onrte-attribution-chip`), while its links are decoration only — `pointer-events: none` so any click opens the Info panel.

### Info panel (About, disclosures and attribution footer)

The About branding row pairs the tagline with the OGIS logo, sized by `.onrte-about-logo { height: 44px; width: auto }`.

Privacy uses a native `<details>` element. The `.onrte-disclosure > summary` rule hides the browser marker and renders a `[+]` / `[−]` toggle in the primary colour, while the `.onrte-disclosure-more` / `.onrte-disclosure-less` spans swap the summary label between "Read more" and "Read less" from the `[open]` state.

The Info panel content fills the scroll container (`.onrte-info-panel { min-height: 100% }`), so the attribution block (`.onrte-attribution-section`) — an unheaded footer — can sit flush at the panel's bottom edge. Its `margin-top: auto` pushes it down when content is short, and `position: sticky; bottom: 0` (with the panel's frosted glass) keeps it pinned there while overflowing content scrolls behind it:

```scss
.onrte-info-panel {
  min-height: 100%;
}

.onrte-attribution-section {
  margin-top: auto;
  position: sticky;
  bottom: 0;
  z-index: 2;
  background: rgba(255, 255, 255, 0.92);
  backdrop-filter: blur(20px) saturate(160%);
  -webkit-backdrop-filter: blur(20px) saturate(160%);
}

[data-bs-theme="dark"] .onrte-attribution-section {
  background: rgba(10, 18, 10, 0.92);
}
```

Its links are interactive (`--bs-primary`), unlike the attribution chip's decoration-only links.

### Side panel (`.onrte-panel`)

Semi-transparent background so the map remains visible behind the panel:

```scss
.onrte-panel {
  --bs-offcanvas-bg: rgba(255, 255, 255, 0.82);
  backdrop-filter: blur(20px) saturate(160%);
  border-right: 1px solid rgba(0, 0, 0, 0.07) !important;
  box-shadow: 3px 0 28px rgba(0, 0, 0, 0.08);
}

[data-bs-theme="dark"] .onrte-panel {
  --bs-offcanvas-bg: rgba(10, 18, 10, 0.82);
  border-right: 1px solid rgba(255, 255, 255, 0.07) !important;
  box-shadow: 3px 0 28px rgba(0, 0, 0, 0.4);
}
```

Panel width is controlled via a CSS custom property:

```scss
:root {
  --onrte-panel-width: 340px;
}
```

### Icon buttons (`.icon-btn`)

Inactive icons use `--bs-secondary-color`. The active panel state and hover use `--bs-primary` with a 0.15 s ease transition. The `[aria-pressed="true"]` rule must live in section `#6e`:

```scss
.icon-btn {
  &[aria-pressed="true"] {
    color: var(--bs-primary);
  }
  &:hover {
    color: var(--bs-primary);
  }
}
```

The chip variant (`.icon-btn--chip`) also lightens its glass background on hover/active and has a dark-theme override (`rgba(10, 18, 10, …)` background, `rgba(255, 255, 255, 0.55)` inactive icon colour).

### MapLibre scale bar

MapLibre's `ScaleControl` sits above the bottom-left attribution chip, so the control's bottom offset is raised:

```scss
.maplibregl-ctrl-bottom-left {
  bottom: 3.25rem !important;
}
```

Once the chip collapses to the icon-only pill on the first map drag, the chip sets `data-attrib-collapsed="true"` on `.onrte-root` (driven by [`useAttribution`](../src/composables/useAttribution.js) in [`App.vue`](../src/App.vue)) and the scale moves inline to the right of the ⓘ icon:

```scss
.onrte-root[data-attrib-collapsed="true"] .maplibregl-ctrl-bottom-left {
  bottom: 1.2rem !important;
  left: 4rem !important;
}
```

In dark mode MapLibre's scale control would otherwise remain a bright white box, so it is recoloured to the app's dark glass (background, border and text only — geometry untouched):

```scss
[data-bs-theme="dark"] .maplibregl-ctrl-scale {
  background-color: rgba(10, 18, 10, 0.82);
  border-color: rgba(255, 255, 255, 0.1);
  color: rgba(255, 255, 255, 0.7);
}
```

### Dark mode

Bootstrap 5.3's `data-bs-theme` system is fully supported. The app has no in-app toggle and stores no theme preference — it always follows the operating system/browser `prefers-color-scheme` setting:

- [`useSettings`](../src/composables/useSettings.js) derives `resolvedTheme` (`'light'` or `'dark'`) and `isDark` from a `matchMedia('(prefers-color-scheme: dark)')` change listener, so runtime OS changes apply immediately.
- [`App.vue`](../src/App.vue) applies `:data-bs-theme="resolvedTheme"` on `.onrte-root` — the single DOM application point.
- `useSettings` also emits `theme:change` (`'dark'` / `'light'`) on the shared emitter when the system preference changes. It has no consumers yet — reserved for future map style integration.

On Route-specific overrides include dark variants for the panel, corner chips, the Info attribution footer and the MapLibre scale control.
